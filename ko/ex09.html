제9부 연습문제

제9부(깊은 구석들)의 장들, 52–58장에서 낸 문제를 모았다. 해답은 책 끝의 「연습문제 해답」에 부별로 있다. 틀리는 것이 전제된 문제들이다 — 풀지 못하면 해답의 설명을 읽으며 배우면 된다.

문제 9-1. f() * g() + h() 에서 「곱셈이 덧셈보다 우선순위가 높으니 f 와 g 가 h 보다 먼저 불린다」고 했다. 이 말을 판정하라. 세 함수가 모두 같은 전역 변수를 바꾼다면 무엇이 문제가 되는가? (해답)

문제 9-2. 다음 줄은 「a 와 b 를 비트 AND 한 결과가 c 와 같은가」를 물으려고 쓴 것이다. 실제로는 무엇을 계산하는가? 그리고 「조건식 뒤의 대입」인 a ? b : c = d 는 왜 오류인가?

if (a & b == c) ...

(해답)

문제 9-3. uint32_t 의 아래 w 비트를 켜는 마스크를 (1u << w) - 1u 로 만들었다. w 가 0 부터 32 까지 올 수 있다. 어느 값에서 무엇이 잘못되는가? 어떻게 고치는가? (해답)
문제 9-4. if (0.1 + 0.2 == 0.3) 이 거짓이 되어 if (fabs(a - b) < 1e-9) 로 바꿨다. 이 고침이 맞는 경우와 틀리는 경우를 들어라. 허용치는 어디서 정해야 하는가? (해답)
문제 9-5. x 가 NaN 이면 x == x 는 무엇인가? NaN 이 섞인 배열을 qsort 로 정렬하면 무슨 일이 생길 수 있는가? (해답)

문제 9-6. 55장의 safe_div 가 0 으로 나누기만 막고 있었다고 하자. 다음 코드에서 빠진 실패 조건 하나와 빠진 전제 하나를 찾아라. 그리고 실패할 때 *out 을 건드리지 않는다는 약속은 왜 계약의 일부인가?

[[nodiscard]] bool safe_div(int a, int b, int *out)
{
    if (b == 0) return false;
    *out = a / b;
    return true;
}

(해답)

문제 9-7. 「[[nodiscard]] 를 붙였으니 반환값을 버린 코드는 컴파일되지 않는다」 — 이 말을 판정하라. 표준이 약속하는 것은 무엇이고, 실제로 빌드를 멈추게 하려면 무엇이 더 필요한가? (해답)

문제 9-8. 다음 함수에서 컴파일러가 널 검사를 지워 버릴 수 있다. 왜 그런가? 이것이 실제 취약점으로 이어진 사례는 무엇인가?

int first_len(struct dev *d)
{
    int n = d->len;
    if (d == NULL) return -1;
    return n;
}

(해답)

문제 9-9. 정의되지 않은 동작(UB) · 미지정 동작 · 구현 정의 동작의 차이를 한 줄씩 적고, 각각의 예를 하나씩 들어라. (해답)
문제 9-10. 네트워크 버퍼에서 4 바이트 정수를 uint32_t v = *(uint32_t *)(buf + 3); 으로 꺼냈다. 「x86 에서 잘 돌았으니 정렬은 상관없다」는 말에 답하고, 어떻게 꺼내야 하는가? (해답)
문제 9-11. 「도구를 돌려 아무것도 안 나왔으니 이 코드에는 메모리 사고가 없다」 — 이 말이 틀린 까닭을 말하라. 시험 빌드에서 먼저 켤 도구는 무엇이고, 그것이 놓치는 사고의 갈래는 무엇인가? (해답)
문제 9-12. 「가비지 컬렉터가 있는 언어에서는 누수가 없다」 — 판정하라. 그 언어에서도 일어나는 누수의 예를 둘 들어라. (해답)
문제 9-13. C23 의 unreachable() 을 「여기는 절대 오지 않는다」는 주석 대신 쓰려 한다. 이 매크로는 무엇을 하는가? 「사실은 올 수 있는」 자리에 쓰면 무슨 일이 생기는가? (해답)
