돌아보기

101장 에서 모든 입력 숫자가 64비트 범위에 들어가는지 이미 확인했다. 그러면 각 원소가 INT64_MIN 과 INT64_MAX 사이인데도 그 합계는 넘칠 수 있는가 — 그리고 부호 없는 uint64_t 로 더해 wrapped < a 인지 물으면 깔끔하게 해결되지 않는가?

답. 둘 다 함정이다. 첫째, INT64_MAX 와 1 은 각각은 올바른 64비트 정수지만 더하는 순간 64비트 범위를 넘는다 — 부호 있는 덧셈 넘침은 정의되지 않은 동작이다(56장).

★ 둘째, uint64_t 로 감아 돌리고 wrapped < a 로 사후 검사하는 관용구는 양수 두 개만 더할 때만 성립한다. CSV 에 음수 -3 이 들어오는 순간 10 + (uint64_t)-3 은 감겨 7 이 되고, 7 < 10 이 참이라 정상 계산을 넘침으로 오진한다.

이 장의 필요성과 맥락

96장 에서 <stdckdint.h> 의 규칙을 따로 떼어 배웠다. 이 장은 그 도구를 101장 가 미뤄 둔 acc += val 한 줄에 꽂아 넣으면서, 부호 있는 넘침·거짓 양성을 일으키는 손수 짠 검사·그리고 실패했을 때 호출자의 출력 변수를 건드리지 않는 계약까지 한 흐름으로 검증한다.

이 장이 끝나면

이 장을 마치면 두 가지를 실물로 확인한다. 먼저 부호 없는 사후 검사가 10 + (-3) 을 왜 거짓 넘침으로 잡는지 보고, 이어 ckd_add 가 양의 경계(INT64_MAX,1), 음의 경계(INT64_MIN,-1), 중간 회복 순서(INT64_MAX,-1,1)를 어떻게 처리하고 실패 시 *out 을 손대지 않은 채 남기는지 본다.

이 장에서 답할 질문

  1. 개별 필드가 64비트를 넘은 것(ERANGE)과 합산이 넘친 것(ckd_add)을 굳이 나누어 보고해야 하는가?
  2. C23 을 못 쓰는 옛 컴파일러에서는 ckd_add 대신 무엇을 쓰는가?

102.1 왜 사후 검사는 음수에서 뒤집히나#

부호 있는 정수를 더한 뒤 if (sum < acc) 를 묻는 코드는 96장 에서 보았듯 컴파일러가 넘침이 일어나지 않는다고 가정하고 조건문을 지울 수 있어 이미 계약 밖이다. 그러면 감아 돌기가 정의된 uint64_t 로 옮겨서 같은 검사를 하면 안전해질까. 다음 시연의 첫 두 줄이 그 답을 낸다.

examples/sumcsv/03-overflow/checked_sum.c

/* C23 <stdckdint.h> 의 ckd_add 로 누적 넘침을 막고, 실패 시 출력 변수를 건드리지 않는다. */
#include <errno.h>
#include <inttypes.h>
#include <limits.h>
#include <stdckdint.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

static bool sum_checked(const char *line, int64_t *out, const char **why)
{
    int64_t acc = 0;
    const char *p = line;
    for (;;) {
        errno = 0;
        char *end = nullptr;
        long long v = strtoll(p, &end, 10);
        if (end == p || errno == ERANGE) {
            *why = "bad integer or out of range";
            return false;
        }
        if (ckd_add(&acc, acc, (int64_t)v)) {
            *why = "sum overflow";
            return false;
        }
        while (*end == ' ' || *end == '\t') end++;
        if (*end == ',') { p = end + 1; continue; }
        if (*end == '\0' || *end == '\n') break;
        *why = "unexpected character";
        return false;
    }
    *out = acc;
    return true;
}

int main(void)
{
    /* 부호 없는 사후 검사(sum < prev)가 음수 덧셈을 어떻게 오진하는지 먼저 본다 */
    uint64_t a = 10;
    uint64_t b = (uint64_t)(int64_t)-3;
    uint64_t wrapped = a + b;
    printf("[naive post-check] 10 + (-3) as uint64 = %" PRIu64 " (< 10 => false overflow: %s)\n",
           wrapped, wrapped < a ? "yes" : "no");

    const char *cases[] = {
        "10,-3",
        "9223372036854775807,1",
        "-9223372036854775808,-1",
        "9223372036854775807,-1,1",
        "5000000000000000000,5000000000000000000",
        "-5000000000000000000,-5000000000000000000",
    };

    puts("\n[ckd_add boundary checks]");
    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; i++) {
        int64_t out = -999;
        const char *why = "ok";
        bool ok = sum_checked(cases[i], &out, &why);
        if (ok) {
            printf("  %-44s -> ok: %" PRId64 "\n", cases[i], out);
        } else {
            printf("  %-44s -> err: %s (out preserved: %" PRId64 ")\n",
                   cases[i], why, out);
        }
    }
    return 0;
}

실행 결과

[naive post-check] 10 + (-3) as uint64 = 7 (< 10 => false overflow: yes)

[ckd_add boundary checks]
  10,-3                                        -> ok: 7
  9223372036854775807,1                        -> err: sum overflow (out preserved: -999)
  -9223372036854775808,-1                      -> err: sum overflow (out preserved: -999)
  9223372036854775807,-1,1                     -> ok: 9223372036854775807
  5000000000000000000,5000000000000000000      -> err: sum overflow (out preserved: -999)
  -5000000000000000000,-5000000000000000000    -> err: sum overflow (out preserved: -999)

첫 출력 줄 [naive post-check] 를 보라. a = 10 에 -3 을 부호 없는 값으로 더하면 2의 보수 표현에서 wrapped = 7 이 나오고, 7 < 10 이 참이므로 false overflow: yes 가 찍힌다. 올바른 합 7 을 넘침으로 거부한 것이다.

sumcsv 는 명세상 음수와 양수를 모두 받는 도구다(100장). 증가분만 오는 경우에만 맞는 조건을 양수·음수가 섞인 입력에 쓰면, 유효한 음수가 들어오는 족족 거짓 오류를 낸다. C23 <stdckdint.h> 의 ckd_add(&acc, acc, val) 은 두 피연산자의 부호와 목적지 타입 int64_t 를 직접 따져 참 수학적 합이 표현 범위 안에 들어가는지를 판정하므로 이런 부호 함정이 없다.

102.2 ckd_add 경계 표와 실패 원자성#

시연 후반부의 여섯 표본이 sum_checked 의 경계 동작을 전부 보여 준다.

눈여겨볼 자리가 둘 있다.

첫째, 모든 실패 줄 끝에 찍힌 out preserved: -999 다. sum_checked 는 매개변수 *out 을 누적기로 쓰지 않고 함수 안의 지역 변수 acc 에만 더한 뒤, 루프가 성공적으로 끝난 33행에서 한 번만 *out = acc; 를 적는다. ckd_add 가 실패하는 순간 acc 에는 wrapped 된 쓰레기 값이 들어 있을 수 있지만, 호출자의 out 은 -999 그대로 남는다.

#include <stdckdint.h>
#include <stdint.h>

bool add_into(int64_t *out, int64_t a, int64_t b)
{
    int64_t tmp = 0;
    if (ckd_add(&tmp, a, b)) return false;  /* 실패 시 *out 불변 */
    *out = tmp;
    return true;
}

둘째, 표의 넷째 행 9223372036854775807,-1,1 과 그 순서를 바꾼 9223372036854775807,1,-1 은 최종 수학적 합이 둘 다 INT64_MAX 로 같지만 후자는 두 번째 항 1 을 더하는 순간 중간 합이 넘쳐 오류로 거부된다. 왼쪽에서 오른쪽으로 순서대로 더하며 매 단계 64비트 범위를 지키는 것이 1판 계약이다 — 재정렬은 하지 않는다.

반례. *out 을 직접 누적기로 넘겨 ckd_add(out, *out, val) 부르기

ckd_add 는 넘침이 일어나면 true 를 돌려줄 뿐만 아니라, 수학적 합을 목적지 타입 폭으로 자른 하위 비트를 첫 번째 인자에 써 넣는다. ckd_add(out, *out, val) 처럼 호출자의 변수를 직접 넘기면, 실패로 돌아간 뒤에도 *out 에 감아 돌아간 값이 남아 「실패하면 상태를 바꾸지 않는다」는 약속이 깨진다.

문. 개별 필드가 64비트를 넘은 것(ERANGE)과 합산이 넘친 것(ckd_add)을 굳이 나누어 보고해야 하는가?

답. 두 오류는 고치는 자리가 다르다. 99999999999999999999 처럼 필드 하나가 범위 밖이면 그 필드가 틀렸다는 뜻이고(integer out of range), 5000000000000000000,5000000000000000000 처럼 각 필드는 맞는데 합산에서 넘치면 줄 전체의 누적이 64비트 표현을 넘었다는 뜻이다(sum overflow). 호출자나 사용자가 메시지를 읽고 원인을 바로 짚을 수 있도록 갈라 둔다.

문. C23 을 못 쓰는 옛 컴파일러에서는 ckd_add 대신 무엇을 쓰는가?

답. 96장 에서 본 것처럼 HAVE_CKDINT 가드 아래 GCC·Clang 의 __builtin_add_overflow 로 채우거나, 부호 조합을 따져 사전 검사 함수를 한곳에 감싼다. 어느 쪽이든 계약(ckd_add 처럼 호출 전 범위 검사)은 같다.
