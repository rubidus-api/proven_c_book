101 한 줄을 정확히 해석하기 — 파서와 경계 정책

먼저 알아야 할 것

100장 무엇을 만들 것인가 · 1판 입력·오류 계약
44장 안전한 입력 · strtol 의 세 검사
81장 변환 · 할당 · 환경 · strtoll 과 errno
82장 문자 분류 · isdigit 과 (unsigned char)

돌아보기

44장 에서 배운 대로 strtol 계열의 반환값·endptr·errno 를 모두 확인하는 함수를 이미 가지고 있다. 그 함수로 한 필드를 읽은 다음, 쉼표가 있으면 건너뛰고 줄 끝에 닿으면 멈추면 한 줄 파서가 완성되지 않는가?

답. 필드 안의 검사만으로는 필드 사이와 줄 양끝의 규칙을 세우지 못한다. ",10\n", "10,,30\n", "10,20,\n", "10 20\n", " \n" 같은 입력은 모두 strtoll 자체의 오류가 아니라 쉼표·공백·줄 끝 사이의 경계에서 가려야 한다.

★ 게다가 strtoll 은 호출 전에 선행 공백을 스스로 건너뛰기 때문에, isspace 가 포함하는 \n·\r·\v 까지 필드의 일부로 먹어 버릴 수 있다. 그래서 정수를 부르기 전에 어디까지를 공백으로 볼지와 필드 첫 글자가 부호·숫자인지를 먼저 검사해야 한다.

이 장의 필요성과 맥락

100장 에서 세운 계약이 첫 번째 구현으로 내려오는 자리다. 이 장은 44장 의 한-정수 파서를 한-줄 CSV 파서로 끌어올리면서, 입출력이나 파일 분리와 섞지 않고 순수하게 구문·구분자·범위 경계만 메모리 위 문자열로 검증한다.

이 장이 끝나면

이 장을 마치면 1판 파서가 어떤 입력을 통과시키고 어떤 입력을 왜 거부하는지 열한 개 표본으로 확인한다. 아울러 공백 정책(' '/'\t'), (unsigned char) 캐스트, 64비트 범위 확인, 그리고 실패 시 호출자 출력 변수를 건드리지 않는 구조까지 갖춘다.

이 장에서 답할 질문

  1. sum_line 이 실패했을 때 *out_sum 에 0 을 적어 두면 편하지 않은가?
  2. parse_line.c 의 77행 acc += val; 는 안전한가?

101.1 한 줄 전체의 구문과 필드 경계#

다음 시연은 앞 장(100장)에서 정한 구문 계약을 메모리 위 문자열 열한 개에 대고 시험한다. 입출력이나 덧셈 넘침 검사는 아직 끼우지 않고, 오직 parse_i64_field 와 sum_line 이 줄의 경계를 어떻게 가르는지만 본다.

examples/sumcsv/02-parse/parse_line.c

/* 한 줄 전체의 구문과 필드 경계를 검사한다: 빈 입력 · 빈 필드 · 후행 쉼표 · 범위 초과 · 쓰레기 토큰 거부. */
#include <ctype.h>
#include <errno.h>
#include <inttypes.h>
#include <limits.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

static const char *skip_ws(const char *p)
{
    while (*p == ' ' || *p == '\t') p++;
    return p;
}

static bool at_eol(const char *p)
{
    return *p == '\0' || *p == '\n' || (*p == '\r' && p[1] == '\n');
}

static bool parse_i64_field(const char *start, const char **out_rest,
                            int64_t *out_val, const char **out_why)
{
    const char *p = skip_ws(start);
    if (at_eol(p) || *p == ',') {
        *out_why = "empty field";
        return false;
    }
    const char *digits = p;
    if (*digits == '+' || *digits == '-') digits++;
    if (!isdigit((unsigned char)*digits)) {
        *out_why = "bad integer";
        return false;
    }

    errno = 0;
    char *end = nullptr;
    long long v = strtoll(p, &end, 10);
    if (end == p) {
        *out_why = "bad integer";
        return false;
    }
    if (errno == ERANGE) {
        *out_why = "integer out of range";
        return false;
    }
#if LLONG_MIN < INT64_MIN || LLONG_MAX > INT64_MAX
    if (v < INT64_MIN || v > INT64_MAX) {
        *out_why = "integer out of range";
        return false;
    }
#endif

    *out_val = (int64_t)v;
    *out_rest = end;
    return true;
}

static bool sum_line(const char *line, int64_t *out_sum, const char **out_why)
{
    if (!line || *line == '\0') {
        *out_why = "empty input";
        return false;
    }
    const char *p = skip_ws(line);
    if (at_eol(p)) {
        *out_why = "empty input";
        return false;
    }

    int64_t acc = 0;
    for (;;) {
        int64_t val = 0;
        const char *rest = nullptr;
        if (!parse_i64_field(p, &rest, &val, out_why)) return false;
        acc += val;
        p = skip_ws(rest);
        if (*p == ',') {
            p++;
            if (at_eol(skip_ws(p))) {
                *out_why = "trailing comma";
                return false;
            }
            continue;
        }
        if (*p == '\r' && p[1] == '\n') p += 2;
        else if (*p == '\n') p++;
        if (*p == '\0') {
            *out_sum = acc;
            return true;
        }
        *out_why = "unexpected character";
        return false;
    }
}

static void print_case_label(const char *s)
{
    char buf[32];
    size_t j = 0;
    buf[j++] = '"';
    for (size_t i = 0; s[i] && j + 4 < sizeof buf; i++) {
        if (s[i] == '\n') { buf[j++] = '\\'; buf[j++] = 'n'; }
        else if (s[i] == '\r') { buf[j++] = '\\'; buf[j++] = 'r'; }
        else { buf[j++] = s[i]; }
    }
    buf[j++] = '"';
    buf[j] = '\0';
    printf("  %-26s", buf);
}

int main(void)
{
    const char *cases[] = {
        "10,20,30\n",
        "  -5 , +12 , 3 \r\n",
        "0",
        "",
        "   \n",
        ",10\n",
        "10,,30\n",
        "10,20,\n",
        "10,x,30\n",
        "10 20\n",
        "99999999999999999999\n",
    };

    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; i++) {
        int64_t sum = -1;
        const char *why = "";
        print_case_label(cases[i]);
        if (sum_line(cases[i], &sum, &why)) {
            printf(" -> ok: %" PRId64 "\n", sum);
        } else {
            printf(" -> err: %s\n", why);
        }
    }
    return 0;
}

실행 결과

  "10,20,30\n"               -> ok: 60
  "  -5 , +12 , 3 \r\n"      -> ok: 10
  "0"                        -> ok: 0
  ""                         -> err: empty input
  "   \n"                    -> err: empty input
  ",10\n"                    -> err: empty field
  "10,,30\n"                 -> err: empty field
  "10,20,\n"                 -> err: trailing comma
  "10,x,30\n"                -> err: bad integer
  "10 20\n"                  -> err: unexpected character
  "99999999999999999999\n"   -> err: integer out of range

출력을 한 줄씩 계약과 대조한다.

코드에서 작은 장치 세 가지가 이 표 전체를 떠받친다.

  • 직접 고른 공백 건너뛰기(skip_ws) — #include <ctype.h> 의 isspace 는 \n·\r·\v·\f 와 로케일 의존 공백까지 건너뛴다(82장). 한 줄 안의 수평 공백만 허용하려면 ' ' 과 '\t' 만 짚어 넘기는 편이 낫다.
  • (unsigned char)*digits 캐스트 — char 가 부호 있는 플랫폼에서 음수 바이트를 그대로 isdigit 에 넘기면 정의되지 않은 동작이다. 비-ASCII 바이트가 입력에 섞일 수 있는 파서에서는 반드시 unsigned char 로 바꾼다.
  • 플랫폼별 정수 폭 방어 — #if LLONG_MIN < INT64_MIN || LLONG_MAX > INT64_MAX 가 long long 이 int64_t 보다 넓은 환경에서 errno == ERANGE 로 안 잡히는 범위 초과를 한 번 더 막는다(81장).

흔한 오해. “strtoll 이 숫자를 읽고 멈춘 자리가 , 나 '\\0' 인지만 보면 충분하다”

두 가지가 새어 나간다. 첫째, strtoll 은 호출되자마자 앞쪽의 세로 공백(\n, \r, \v, \f)도 스스로 건너뛴다. skip_ws 로 ' ' 와 '\t' 만 넘긴 뒤 digits 위치가 정말 숫자인지 먼저 보지 않으면, 줄 경계를 넘는 공백이나 비정상 제어 문자가 파서 안으로 스며든다.

둘째, "10,20,\n" 같은 끝 쉼표나 ",10\n" 같은 첫 쉼표는 숫자를 읽고 멈춘 자리만 보아서는 걸러지지 않는다. 쉼표를 소비하는 상태 전이 자체가 「쉼표 뒤에는 반드시 빈 칸이 아닌 다음 필드가 와야 한다」고 검사해야 한다.

문. sum_line 이 실패했을 때 *out_sum 에 0 을 적어 두면 편하지 않은가?

답. 호출자가 실패 시 이전 값 또는 감시 값을 유지하려 할 때 오히려 방해가 된다. 실패하면 출력 포인터를 건드리지 않고, 검사를 끝까지 통과한 맨 끝 한 줄에서만 *out_sum = acc; 를 적는다. sum_line 자체가 실패 시 상태를 남기지 않는 작은 계약이다.

문. parse_line.c 의 77행 acc += val; 는 안전한가?

답. 안전하지 않다. 이 장의 코드는 개별 필드가 64비트 범위에 들어가는지만 errno == ERANGE 로 막을 뿐, 두 정수를 더하는 acc += val 에서 생기는 부호 있는 덧셈 넘침은 막지 못한다. 바로 다음 장(102장)이 그 한 줄을 고치는 장이다.

101.2 한 줄을 끝내는 at_eol 의 역할#

윈도 줄 끝 \r\n 과 유닉스 줄 끝 \n, 그리고 마지막 줄에 개행이 없는 '\0' 세 가지를 at_eol 하나로 묶었다. 주목할 점은 \r 단독은 줄 끝으로 치지 않고 반드시 \r\n 짝만 벗긴다는 것이다. 쉼표 뒤 빈 필드 검사와 줄 끝 소비 두 곳 모두 같은 at_eol 과 같은 짝 규칙을 써야 " -5 , +12 , 3 \r\n" 은 통과하고 "10,20,\r\n" 은 "trailing comma" 로 정확히 잡힌다.

복습 정리

한 줄의 구문과 쉼표 경계는 세웠다. 다음 장(102장)에서는 그대로 남아 있던 acc += val 을 C23 <stdckdint.h> 로 바꾸고, 왜 흔한 사후 덧셈 검사가 음수에서 거꾸로 오동작하는지 확인한다.
