# RFC-0004: 제11부 — proven 매뉴얼부의 완성

- Status: Accepted
- Date: 2026-08-05
- Scope: 제11부(현 47–49장)를 라이브러리 전체를 다루는 매뉴얼부로 확장.
  다른 부의 내용은 건드리지 않는다(참조 갱신 제외).
- 전제: RFC-0001 교수 설계, RFC-0002 §1 구성 원리, RFC-0003 용어 병기.
- 사용자 지시 (요약): proven_c_lib의 매뉴얼을 참고해 *완전한 proven
  매뉴얼*을 책 마지막 부분에 자연스럽게 잇는다. 그간 배운 C의 문제점·
  취약점과 이어서, 초보자에게 친절하게 예시로 **필요성을 먼저 보이고**,
  그에 대한 대응으로 각 부분·기능·사용법·**정례와 반례**를 다양하게
  서술한다. 계획을 RFC로 먼저 세우고 여러 단계로 나누어 진행한다.

## 1. 설계 원리

**P1 — 필요가 먼저, 도구는 나중.** 어떤 장도 API 소개로 시작하지 않는다.
각 절은 [C로 그 일을 하는 평범한 코드 → 그 코드가 조용히 지고 있는
위험(앞 장들에서 이미 배운 것) → proven의 대응 → 대가]의 순서를 지킨다.
이 순서를 어기는 절은 매뉴얼이지 이 책의 장이 아니다.

**P2 — 앞 장의 회수 장치.** 제11부는 새 지식을 얹는 부가 아니라, 이미
배운 위험들이 *설계로 어떻게 막히는가*를 보이는 부다. 각 절은 자기가
회수하는 장을 명시한다(예: 잘림 → 34장, 앨리어싱 → 11장, 수명 → 36장).

**P3 — 정례와 반례의 짝.** 기능마다 잘 쓴 예(정례)와 잘못 쓴 예(반례)를
짝으로 보인다. 반례는 세 종류를 구별한다.

- *컴파일되지 않는 반례*: `[[nodiscard]]` 무시처럼 빌드가 막는 것. 코드와
  컴파일러 메시지를 지면에 인쇄한다(실행 캡처 아님).
- *컴파일되고 잘못 도는 반례*: 표준 C로 쓴 위험한 코드. 실제로 돌려
  출력을 인쇄한다 — 이것이 가장 강한 교육 자료다.
- *돌지만 계약을 어긴 반례*: 이미 파괴한 것을 다시 쓰기 같은 것. 실행하지
  않고 지면에서 설명한다(UB를 시연하지 않는다는 이 책의 원칙).

**P4 — 매뉴얼로도 쓸 수 있게.** 각 장 끝에 그 모듈의 *요약 표*(함수 —
하는 일 — 실패 조건 — 소유권)를 둔다. 통독한 뒤에는 이 표만 다시 보게
된다. 표는 RFC-0001의 `recap` 장치를 쓴다.

**P5 — 읽기 전용 원칙 유지.** 시키지 않는다. 예제는 전부 지면에서 완결
되며, 검증 스크립트가 실제로 컴파일·실행한 출력을 싣는다.

**P6 — 전체가 아니라 뼈대.** 라이브러리의 모든 함수를 옮겨 적지 않는다.
각 모듈의 *모델*(무엇을 소유하고 무엇을 빌리는가, 어떻게 실패하는가)을
가르치고, 나머지는 헤더와 원 매뉴얼로 보낸다. 이 책이 뜬 뒤에도 낡지 않을
것만 싣는다.

## 2. 장 구성

제11부를 47–56장(10장)으로 재편한다. 기존 47·48·49장의 내용은 새 47·
51·50장에 흡수된다. 제12부(실전의 C·총정리)는 57·58장으로 밀린다.

| 장 | 제목 | 회수하는 앞 장 | 핵심 |
|---|---|---|---|
| 47 | 50년째 출하되는 다섯 가지 버그 | 11·19·34·36·37 | 부의 문제 제기. 다섯 결함을 표준 C 코드로 실연하고, 각각에 대한 답의 이름만 예고 |
| 48 | 시작하기 — 빌드, 그리고 첫 프로그램 | 14·43 | 설치 없는 소스 배포 모델, include, 첫 프로그램, `PROVEN_ARG`의 첫 인상 |
| 49 | 에러는 값이다 | 41·42 | `proven_err_t`, `proven_result_*`, `proven_is_ok`, `[[nodiscard]]`, 패닉의 자리 |
| 50 | 기반 — 바이트, view, 크기 산술 | 11·30·32·34 | `proven_byte_t`와 앨리어싱 면제, view=포인터+길이, 감기지 않는 크기 산술, 정렬 |
| 51 | 할당은 매개변수다 | 36·37 | 할당자 값·heap·arena·pool·실패 원자성·버퍼 |
| 52 | 문자열과 텍스트 | 7·33·34 | u8str/view, 소유와 빌림, 거부하되 자르지 않기, 분할·검색, u16과 경계 |
| 53 | 형식화와 파싱 | 19·22·45 | `{}` 문법과 `_Generic`, 포맷 불일치의 소멸, 스캐너 |
| 54 | 컨테이너와 알고리즘 | 32·38 | 동적 배열·침습적 리스트·링·맵, introsort, 용도별 해시, hex/Base64 |
| 55 | 바깥 세계 — 파일, 스트림, 시간, 난수 | 22·50 | 파일시스템·버퍼드 스트림·시간·난수·메모리 매핑 |
| 56 | 경계 — 코루틴, 작업, 그리고 OS가 없을 때 | 10·36 | 스택리스 코루틴·job·스레드와 출처·PAL·freestanding·언제 쓰지 않는가 |

각 장은 RFC-0001 §5 장 템플릿을 그대로 따른다(선행조직자 → 심화 문답 →
본문(문답·오개념 ≥1·실제 사례 ≥1) → 요약 표 → 다리 문단).

## 3. 장치 확장

**반례 상자 신설.** `#antipattern[제목][본문]` — 붉은 갈색 계열, 아이콘
`✗`. 오개념 상자(⚠, 독자의 *생각*이 틀린 경우)와 구별한다. 반례 상자는
*코드*가 틀린 경우에 쓴다.

`#demo`는 그대로 쓴다. 컴파일되지 않는 반례는 새 인자
`#demo(..., expect-error: "…")`가 아니라, 예제 디렉터리 밖의 순수 `raw`
블록 + 컴파일러 메시지 인용으로 처리한다(검증 스크립트를 오염시키지
않기 위해서다).

## 4. 예제 정책

- 위치: `examples/ch47/` … `examples/ch56/`.
- 이름: 기능을 드러내는 짧은 영어 명사(`arena.c`, `split.c`).
- 반례 중 *컴파일되고 잘못 도는 것*은 `_bad` 접미사를 붙여 같은 디렉터리에
  둔다(`copy_bad.c`). 이것도 검증 대상이다 — 경고 없이 컴파일되어야
  한다는 사실 자체가 교훈이기 때문이다.
- `-Werror`와 충돌하는 반례(의도적 미사용 변수 등)는 예제로 만들지 않고
  지면 코드로만 보인다.
- 모든 문자열은 영어(사용자 지시). 유니코드 시연은 예외.

## 5. 단계 (각 단계 = 커밋 1개, 단계 끝마다 빌드·검증·육안 확인)

- **S0** RFC 확정 (이 문서) + `rfc-0000-index.md` 갱신.
- **S1** 용어 병기 스윕 (RFC-0003). 제11부와 무관하게 먼저 끝낸다.
- **S2** 뼈대 이동: 50·51장 → 57·58장 renumber(2단계 치환), 제11부 장
  파일 10개 생성, `main.typ` 부 표 갱신, 참조 갱신, 빌드 그린.
- **S3** 47장(다섯 가지 버그) — 부의 문제 제기. 반례 예제 4~5종.
- **S4** 48·49장 (시작하기 / 에러는 값이다).
- **S5** 50·51장 (기반 / 할당).
- **S6** 52·53장 (문자열 / 형식화·파싱).
- **S7** 54장 (컨테이너와 알고리즘).
- **S8** 55·56장 (바깥 세계 / 경계).
- **S9** 부 전체 통독 교정: 장치 균형, 회수 표(P2) 정합, 요약 표 형식
  통일, 상호참조 검사, 최종 PDF.

각 단계는 이전 단계의 결과를 다시 읽고 시작한다(사용자 지시: 여러 단계로
길게 검토해 가면서 차근차근).

## 6. 위험과 대비

- **분량 폭주**: 원 매뉴얼은 50만 자가 넘는다. P6(뼈대만)과 장별 요약 표로
  묶는다. 목표는 장당 6–10쪽.
- **참조 깨짐**: renumber는 두 단계 치환(플레이스홀더)으로만 한다 —
  LESSONS.md에 기록된 사고 재발 방지.
- **API 표류**: 벤더된 proven은 v26.07.23d로 고정되어 있다. 책은 그 버전을
  기준으로 쓰고, 판권에 버전을 밝힌다.
- **홍보처럼 읽힘**: 각 절은 반드시 *대가*를 함께 적는다(원 매뉴얼의
  미덕이다). 쓰지 않는 편이 나은 경우도 56장에서 명시한다.
