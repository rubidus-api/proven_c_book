# RFC-0001: 교수 설계 (Pedagogy)

- Status: Accepted
- Date: 2026-08-04
- Scope: 책 전체의 서술 구조와 학습 장치. 장 구성(목차)은 RFC-0002가 다룬다.
- 전제된 확정 결정: 읽기 전용 문답형 학습 — 실습·연습 배제 (DECISIONS 2026-08-04, R16·R17)

## 1. 목표와 독자 모델

이 책은 프로그래밍을 한 번도 해 본 적 없는 독자가, 시키는 것 없이 **그냥
읽기만 해도** 전산의 기본 개념과 모던 C(C23)를 익히게 되는 책이다.

독자 모델:

- 사전 지식: 없음. 변수·메모리·프로그램이라는 낱말의 기술적 의미를 모른다.
- 수학: 중등 수준의 산술·간단한 대수까지만 가정한다. 그 이상이 필요하면 본문에서 만들어 준다.
- 행동 모델: 독자는 소설처럼 앞에서 뒤로 읽는다. 컴퓨터 앞에 앉아 있지 않을 수 있다. 따라서 지면 위에서 모든 것이 완결되어야 한다.

## 2. 근거 원리와 서술 장치 매핑

학습과학의 확립된 원리를, 읽기 전용이라는 제약 아래에서 구현 가능한 서술
장치로 번역한다. 각 원리는 "무엇을 하라"가 아니라 "지면이 무엇을 대신
해 주는가"로 구현된다.

| 원리 (학습과학) | 통상 구현 | 이 책의 구현 (읽기 전용) |
|---|---|---|
| 인출 연습 (retrieval practice) | 장말 퀴즈·연습문제 | **본문 문답**: 질문을 읽는 순간 독자의 머릿속에서 인출이 일어나고, 바로 다음 줄에서 답을 확인한다 |
| 간격 반복 (spaced repetition) | 복습 과제 | **다음 장 심화 문답**: 다음 장 서두에서 이전 장 내용을 더 깊은 질문으로 다시 소환한다 |
| 자기설명 효과 (self-explanation) | "왜 그런지 설명해 보라" | 문답의 답이 **모범 자기설명**을 그대로 보여 준다 — 독자는 설명을 따라 읽으며 같은 추론을 재연한다 |
| 예제 기반 학습 (worked examples) | 실습 과제 | 모든 코드는 **저자가 지면에서 처음부터 끝까지 시연**한다. 실행 결과까지 지면에 인쇄한다 |
| 인지부하 관리 (cognitive load) | — | 한 절에 새 개념 하나. 예제는 직전 예제에서 한 가지만 바꾼다(변형 시연). 외재 부하 요소(불필요한 문법 나열) 배제 |
| 오개념 기반 교수 (conceptual change) | 오답 분석 문제 | **오개념 블록**: "이렇게 생각하기 쉽다 → 왜 그럴듯한가 → 실제로는 왜 다른가"를 서술로 완결 |
| 구체→추상 (concreteness fading) | — | 실제 사례·물리적 비유로 시작해 수학적 정의로 착지한다. 착지점은 항상 정확한 수학이다 (R07) |
| 선행조직자 (advance organizer) | — | 장 서두에 "이 장이 끝나면 무엇을 알게 되는가"를 한 문단으로 제시 |
| 이중 부호화 (dual coding) | — | 메모리·비트·자료구조는 그림과 글을 병행한다 |
| 흥미·관련성 (situational interest) | — | 실제 사례를 자주 제시한다 (R10): 실무 사고 사례, 하드웨어 현실, proven 라이브러리가 실제로 푸는 문제 |

## 3. 서술 장치 정의

본문을 구성하는 반복 장치는 다음 여섯 가지다. Typst 함수로 각각 구현한다
(§6).

### 3.1 문답 (즉문즉답) — 기본 리듬

본문 서술 중 독자가 마침 품었을 법한 질문을 그 자리에서 던지고, 바로
답한다. 이것이 책의 기본 리듬이며 가장 자주 나타난다.

규칙:

- 질문은 독자의 목소리다: 방금 읽은 내용에서 자연스럽게 생기는 의문이어야 한다. 저자가 가르치고 싶은 것을 묻는 척하면 안 된다.
- 답은 질문 바로 아래에 온다. 페이지를 넘기게 하거나 "뒤에서 다룬다"로 미루는 답은 문답 장치로 쓰지 않는다.
- 답이 끝나면 본문 서술로 자연스럽게 복귀한다.

### 3.2 심화 문답 (장 서두 회고) — 복습의 유일한 형태

각 장의 서두(선행조직자 문단 다음)에 **이전 장(들)의 내용을 소재로 한
더 깊은 질문과 답** 2~4개를 둔다. 단순 재확인이 아니라, 이전 개념을 새
각도에서 다시 보게 하는 질문이어야 한다.

예 (2장에서 1장의 이진 표현을 회고): "1장에서 8비트로 0부터 255까지 셀 수
있다고 했다. 그러면 256을 더하면 무슨 일이 일어나는가?" — 답하면서
모듈러 산술을 예고한다.

규칙:

- 심화 문답은 다음 장의 새 내용과 연결되는 다리 역할을 겸한다.
- 외울 것이 있는 장은 심화 문답 앞에 **가벼운 복습 정리**(표 또는 목록 하나)를 둘 수 있다. 이것이 허용되는 유일한 복습 형태다.
- 퀴즈 형식(답 숨김, 정답 별면)은 금지다. 질문과 답은 항상 붙어 있다.

### 3.3 오개념 블록

장마다 해당 주제에서 입문자가 실제로 갖는 오개념을 최소 1개 명시적으로
다룬다 (R12). 구조는 고정이다: **그럴듯한 생각 → 왜 그럴듯한가(오개념의
합리적 뿌리 인정) → 실제로는 → 확인 방법(지면 시연)**.

### 3.4 실제 사례 블록

개념이 현실에서 문제가 되었거나 쓰이는 실화·실물 사례 (R10). 예: 정수
오버플로가 일으킨 실제 사고, 부동소수점 누적 오차 사례, proven이 검증으로
막는 실제 결함 부류.

### 3.5 수학 기반 박스

개념의 수학적 정의를 정확히 적는 박스 (R07). 본문은 쉬운 말로 설명하고,
박스가 정확한 착지점을 제공한다. 박스를 건너뛰어도 본문 흐름은 끊기지
않아야 한다.

### 3.6 코드 시연

모든 코드는 완성된 형태로 지면에 싣고, 실행 결과를 함께 인쇄한다.
독자에게 입력·실행을 요구하지 않는다. 원한다면 따라 해 볼 수 있도록
예제는 저장소 `examples/`에 있고 전부 자동 검증되지만 (R15), 본문은 이를
전제하지 않는다.

규칙:

- 새 예제는 직전 예제에서 한 가지만 바꾼다. 바뀐 곳을 지면에 표시한다.
- 실행 결과는 검증 스크립트가 실제로 얻은 출력과 일치해야 한다 (수작업 전사 금지 — 빌드에서 결과를 include).

## 4. 금지 목록

- 연습문제, 실습 과제, 도전 과제, 프로젝트 과제.
- "직접 해보라", "확인해 보라", "연습 삼아 …해 보자" 류의 지시.
- 답을 숨기는 퀴즈, 별면 정답지.
- 다음 장으로 미루는 답 ("이건 7장에서 배운다"만 하고 끝나는 문답). 예고는 허용하되, 그 자리에서 줄 수 있는 최선의 답을 먼저 준다.
- 암기 요구. 기억할 가치가 있는 것은 심화 문답이 알아서 다시 데려온다.

## 5. 장 템플릿

RFC-0002의 모든 장은 다음 골격을 따른다.

1. **선행조직자**: 이 장이 끝나면 무엇을 알게 되는가 (한 문단).
2. **심화 문답**: 이전 학습의 회고 질문 2~4개 (1장은 생략).
3. **본문**: 문답 리듬의 서술 + 코드 시연 + 오개념 블록 ≥1 + 실제 사례 ≥1 + 필요시 수학 기반 박스.
4. **(선택) 복습 정리**: 외울 것이 있는 장만, 표/목록 하나.
5. **다리 문단**: 다음 장이 왜 자연스럽게 이어지는가.

## 6. Typst 구현 스케치

서술 장치는 Typst 함수로 통일한다 (이름은 빌드 골격 작업에서 확정):

```typst
#qa[질문][답]              // 3.1 문답
#deepqa[질문][답]           // 3.2 심화 문답 (장 서두 전용)
#misconception[제목][본문]   // 3.3 오개념 블록
#realcase[제목][본문]        // 3.4 실제 사례
#mathbox[제목][본문]         // 3.5 수학 기반 박스
#demo("examples/…", output: auto)  // 3.6 코드 시연 (출력은 검증 산출물에서 include)
```

`#demo`의 출력 자동 include는 R15 검증 스크립트와 결합한다: 스크립트가
예제를 빌드·실행해 출력을 파일로 남기고, Typst가 그 파일을 읽는다. 본문에
인쇄된 실행 결과가 항상 실제 결과임이 기계적으로 보장된다.

## 7. 품질 게이트

표본 장 검토 시 다음을 점검한다:

- 문답 밀도: 펼친 면(양면)마다 문답이 최소 1개 나타나는가.
- 각 장에 오개념 블록 ≥1, 실제 사례 ≥1, 심화 문답 2~4개(1장 제외)가 있는가.
- 금지 목록(§4) 위반이 없는가.
- 문체가 "~이다/~있다"로 일관되는가 (R13).
- 코드 출력이 전부 `#demo` 자동 include인가.

## 8. 대안 검토

- **장말 연습문제**: 통상 방식이지만 사용자 결정으로 배제 (R16). 인출 효과는 본문 문답 + 심화 문답으로 대체한다.
- **별면 정답 퀴즈**: 읽기 흐름을 끊고 "시키는" 성격이 있어 배제.
- **복습 전용 장**: 간격 반복을 별도 장으로 모으는 방식. 흐름이 끊기고 건너뛰기 쉬워, 각 장 서두 분산 배치(3.2)를 택한다.

## 9. 미결

- 문답 밀도의 상한 (과다하면 서술이 끊긴다 — 표본 장에서 조율).
- 심화 문답이 몇 장 전까지 거슬러 올라갈 수 있는가 (기본: 직전 장 중심, 필요시 그 이전).
- 각 블록의 시각 디자인 (Typst 골격 작업에서).
