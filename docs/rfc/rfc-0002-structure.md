# RFC-0002: 책 구성 (장 체계)

- Status: Proposed
- Date: 2026-08-04
- Scope: 부(Part)와 장(Chapter)의 체계, 각 장의 역할과 RFC-0001 장치 매핑.
- 전제: RFC-0001 교수 설계 (읽기 전용 문답형). 기존 C 입문서 목차 답습 금지 (R05).
- 사용자 확정 골격: **1장 배경설명 → 2장 전산의 기본 → 3장 헬로 월드와 개발환경 구축**. 3장은 특정 플랫폼을 제시하되 일반적인 내용을 주로 삼고, 일반적인 컴파일 과정을 바탕으로 gcc·clang 등을 기반으로 설명한다.

## 1. 구성 원리

기존 입문서의 "문법 항목 순서"(자료형→연산자→제어문→함수→배열→포인터…)를
따르지 않는다. 대신 **개념의 의존 순서**를 따른다: 각 장은 앞 장까지의
개념만으로 완전히 설명 가능해야 하고, 다음 장의 심화 문답이 소환할 거리를
남겨야 한다. 문법은 개념이 필요로 하는 시점에 그 개념의 표기법으로
등장한다.

축은 세 가지다:

- **수학적 기반** (R07): 모든 개념은 정확한 수학적 착지점을 갖는다.
- **기계 현실**: C는 기계를 숨기지 않는 언어다. 메모리·비트·컴파일 과정이 이야기의 배경이 아니라 주인공이다.
- **안전 우선**: 오류 처리와 계약(proven의 관점)을 뒤로 미루지 않고, 개념이 등장하는 순간부터 함께 다룬다.

## 2. 부·장 체계

### 제1부 — 바탕 (컴퓨터와 계산)

**1장. 배경설명** [사용자 확정]

프로그래밍이란 무엇인가, 왜 C인가, C의 역사와 현재(C23까지), 이 책의 읽는
법(문답을 따라 읽으면 된다는 것, 실습을 시키지 않는다는 것). 심화 문답
없음(첫 장). 실제 사례: C가 오늘날 실제로 어디에 있는가(운영체제, 임베디드,
인터넷 기반시설).

**2장. 전산의 기본** [사용자 확정]

정보의 표현(비트, 이진법, 수를 세는 다른 방법), 기억과 주소라는 착상,
계산 모델(기계는 단순한 단계를 반복할 뿐이라는 것), 추상화 계층(트랜지스터
→게이트→기계어→언어). 수학 박스: 위치 기수법, 2^n. 오개념: "컴퓨터는
수학을 잘한다"(실제로는 유한하고 근사한다 — 뒤 장들의 씨앗).

**3장. 헬로 월드와 개발환경 구축** [사용자 확정]

첫 프로그램을 지면에서 시연하고, 소스가 실행 파일이 되기까지의 **일반적인
컴파일 과정**(전처리→컴파일→어셈블→링크)을 중심에 둔다. 도구는 gcc와
clang을 기반으로 설명한다. 개발환경은 특정 플랫폼 하나를 예시로 제시하되
(플랫폼 선정은 §4 미결), 내용은 어느 플랫폼에서든 통하는 일반론을 주로
삼는다. 심화 문답: 2장의 추상화 계층 위에서 "컴파일러는 몇 층에서 몇 층으로
내려가는 번역인가".

### 제2부 — 값 (데이터의 수학)

**4장. 정수 — 유한한 수의 세계**

비트 폭, 부호 없는 정수 = 모듈러 산술(수학 박스: mod 2^n 합동), 부호 있는
정수 = 2의 보수, 오버플로. 실제 사례: 오버플로가 일으킨 실제 사고. C 표기:
정수 타입들, C23 `_BitInt`·`<stdint.h>` 우선 관행.

**5장. 이름, 값, 상태**

변수 = 이름 붙은 기억 장소, 대입 = 상태 변화(수학의 등호와 다르다 —
대표 오개념), 타입 = 값의 집합 + 연산의 약속. `const`, 초기화 우선 관행.

**6장. 흐름 — 결정과 반복**

조건과 반복을 2장의 계산 모델과 연결한다(기계는 단순한 단계를 반복할 뿐).
불리언(C23 `bool`), 비교, 루프 불변식의 착상(수학 박스). 코드 시연은
직전 장 예제의 변형으로만 진행.

**7장. 함수 — 이름 붙은 계산**

함수 = 수학적 함수와 절차의 사이(부수효과라는 개념), 인자 전달 = 값 복사
(대표 오개념: "변수를 넘긴다"), 스코프와 수명의 첫 만남. 계약의 착상:
전제조건·후조건 — proven식 사고의 씨앗.

### 제3부 — 기억 (메모리의 현실)

**8장. 메모리 모델 — 객체, 주소, 포인터**

2장의 "기억과 주소"를 C의 객체 모델로 정식화한다. 포인터 = 주소를 값으로
다루는 것. 대표 오개념 다수 배치(포인터≠배열, NULL, 미초기화). 그림(이중
부호화) 집중 사용.

**9장. 연속된 기억 — 배열과 문자열**

배열, 경계, 버퍼 오버런(실제 사례: 역사적 보안 사고), 문자열 = 바이트 열 +
약속(NUL 종단), 텍스트 인코딩과 UTF-8. proven 등장: 경계 검사되는 문자열
처리가 왜 필요한가.

**10장. 수명과 저장 기간**

자동/정적/동적 저장 기간, `malloc`/`free`, 소유라는 개념, 댕글링·이중 해제
(실제 사례). proven의 안전한 할당 관행.

**11장. 자료의 모양 — 구조체와 표현**

구조체, 패딩과 정렬(기계 현실), 표현과 추상의 분리, 리스트·테이블 같은
자료구조의 첫걸음.

### 제4부 — 정밀 (수학과 오류)

**12장. 실수 — 근사의 수학**

부동소수점 = 유한 이진 유리수의 부분집합(수학 박스: IEEE 754), 반올림,
누적 오차(실제 사례), 비교의 함정(대표 오개념: `0.1 + 0.2`). proven의
정확한 float 처리(파싱·포매팅)가 실제로 어려운 문제임을 사례로.

**13장. 오류와 계약**

오류는 예외가 아니라 값이다(C의 방식), 반환값 검사, proven식 계약: 입력
검증·불변식·실패의 명시적 전파. 심화 문답으로 7장의 전제조건을 소환.

**14장. 정의되지 않은 동작 — C의 어두운 계약**

UB란 무엇인가(수학 박스: 부분 함수), 왜 존재하는가(최적화와 이식성),
대표 UB 목록과 회피 관행, 새니타이저와 도구(지면 시연). 실제 사례: UB가
일으킨 실제 결함.

### 제5부 — 구성 (프로그램에서 소프트웨어로)

**15장. 여러 파일 — 분할과 링크**

3장의 컴파일 과정을 다중 파일로 확장. 헤더와 소스, 번역 단위, 내부/외부
연결, 링크 오류 읽는 법. 심화 문답으로 3장 링크 단계 소환.

**16장. 라이브러리 — 표준과 proven**

표준 라이브러리 지형, 왜 보강이 필요한가, proven 라이브러리의 설계
철학(검증된 기본기)과 실제 사용. 지금까지의 예제를 proven 위에서 재구성.

**17장. 모던 C 관행 총정리**

C23 기능 정리(이 책에서 이미 자연스럽게 써 온 것들의 회고), 현대적 C
스타일, 더 나아갈 길(도구, 커뮤니티, 표준 문서 읽는 법). 전권 회고 심화
문답으로 마무리.

## 3. RFC-0001 매핑 요약

- 모든 장: 선행조직자 + 심화 문답(2장부터) + 오개념 ≥1 + 실제 사례 ≥1 + 필요시 수학 박스 (RFC-0001 §5 템플릿).
- 씨앗-회수 구조: 2장 "컴퓨터는 근사한다"→12장, 7장 계약→13장, 3장 컴파일 과정→15장. 심화 문답이 이 다리들을 소환한다.
- proven은 9장에서 처음 등장해 16장에서 전면화된다. 그 전 장들은 표준 C만으로 설명한다(도구를 늘리지 않아 인지부하 관리).

## 4. 미결

- 3장의 예시 플랫폼 선정: 후보는 (a) Windows + WSL/MSYS2, (b) Linux 데스크톱, (c) 둘 다 짧게. 일반론 위주 원칙은 확정, 예시 하나를 무엇으로 하느냐만 남음.
- 장 개수·분할 조정: 집필하며 장이 비대해지면 분할한다 (예: 8장 포인터).
- 부록 구성 (설치 상세, ASCII/UTF-8 표, 연산자 우선순위 등 참조 자료).

## 5. 대안 검토

- **문법 항목 순서** (전통 목차): R05로 배제. 개념 의존 순서가 입문자의 인지부하에 유리하다.
- **프로젝트 관통형** (하나의 프로그램을 책 전체에서 키워 가는 구성): 실습을 시키지 않는 이 책과 충돌하고, 장 간 결합이 강해 읽다 끊기면 복구가 어렵다. 대신 "직전 예제의 변형" 원칙으로 연속성만 취한다.
- **proven 처음부터**: 1~8장부터 proven을 쓰면 "C를 배우는가, 라이브러리를 배우는가"가 흐려진다. 표준 C 먼저, proven은 필요가 증명된 시점(9장)에 도입.
