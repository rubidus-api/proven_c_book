# RFC-0002: 책 구성 (장 체계)

- Status: Accepted
- Date: 2026-08-04 (rev.b: 최소 도구·선언 분리, 나선형 최소 집합. **rev.c: 소형 장 원칙 — 큰 장을 부(部)로 승격, 절을 장으로 분해, 10부 43장**)
- Scope: 부(Part)와 장(Chapter)의 체계, 각 장의 역할과 RFC-0001 장치 매핑.
- 전제: RFC-0001 교수 설계 (읽기 전용 문답형). 기존 C 입문서 목차 답습 금지 (R05).

## 1. 구성 원리

**개념의 의존 순서**: 각 장은 앞 장까지의 개념만으로 완전히 설명 가능해야
하고, 다음 장의 심화 문답이 소환할 거리를 남겨야 한다. 문법은 개념이
필요로 하는 시점에 그 개념의 표기법으로 등장한다.

**사용이 정의보다 먼저다**: 먼저 남이 만든 것을 읽고 쓰는 법(제4부),
그다음 스스로 이름을 만드는 법(제5부).

**나선형 최소 집합** [사용자 확정]: 한 장에 한 주제를 다 넣지 않는다.
최소 집합부터 시작해 뒤 장들이 필요해지는 시점마다 덧붙여 규모를 불린다.
연산자 배분표:

| 시점 | 덧붙는 연산자/수식 요소 |
|---|---|
| 15장 | 기본 산술 최소 집합: `+ - *`, 괄호, 리터럴, 호출 |
| 18장 | 대입 `=` |
| 21·22장 | `/ %`, 비트 연산, 형변환 첫걸음 |
| 23~25장 | 비교, 논리 `&& \|\| !`, 증감 `++ --`, 복합 대입 |
| 26장 | 조건 연산자 `?:`, 쉼표의 함정 |
| 27장 | `& *`(주소·역참조), `sizeof` |
| 35장 | `. ->`, 복합 리터럴 |

연산자 전체 표는 부록 참조 자료.

**소형 장, 빠른 전환** [사용자 확정, rev.c]: 장의 규모를 줄인다.
한 장 = 하나의 착상, 대략 6~12쪽. 독자는 작은 단위를 빠르게 넘어가며
"한 장을 끝냈다"는 완결감을 자주 얻는다(성취 빈도 = 동기 유지).
큰 주제는 부(部)가 담고, 부 안에서 소형 장들이 이어달린다.
RFC-0001 §5 장 템플릿은 소형 장에 맞게 경량 적용한다: 선행조직자 1~2문장,
심화 문답 1~3개, 오개념·실제 사례는 부 안에서 고르게(장마다 강제하지 않음).

축 세 가지(유지): **수학적 기반**(R07) · **기계 현실** · **안전 우선**.

## 2. 부·장 체계 (10부 43장)

### 제1부 — 바탕

**1장. 배경설명** [사용자 확정]
프로그래밍이란 무엇인가, 왜 C인가, 이 책의 읽는 법(문답을 따라 읽으면
된다, 실습을 시키지 않는다). 실제 사례: C가 오늘날 어디에 있는가.
심화 문답 없음(첫 장).

### 제2부 — 전산의 기본과 배경지식 [사용자 확정: 상당한 분량 = 이 부 전체]

이후 모든 부가 심화 문답으로 소환할 배경지식의 저수지. **이중 트랙 서사**:
각 장이 [기계 이야기 ↔ 그 시점의 C 역사] 쌍이다. 관통 명제 — "C의 역사는,
기계가 복잡해질수록 언어가 기계의 별명에서 **추상 기계의 계약**으로
정밀해져 온 역사다". **기능적 역사 원칙**: 고리타분한 연대기·인물 나열은
빼고, 지금의 C를 설명하는 데 필요한 역사만 쓴다.

**2장. 단순한 기계 모델 ↔ C의 탄생**
CPU·메모리·클록, 계산 모델(단순한 단계의 반복), 비트와 이진법. PDP-11
시대의 정직한 별명으로 태어난 C: B→C, Unix, K&R. 수학 박스: 위치 기수법.

**3장. 워드와 주소 ↔ C의 원형**
바이트 열로서의 메모리, 워드(기계의 자연스러운 크기, "32/64비트"의 실제
의미, 레지스터·버스 폭), 주소라는 착상. **리틀/빅 엔디안**(그림 대조,
네트워크 바이트 순서, 실제 사고 사례). 오개념: "메모리를 읽으면 적힌
순서대로 수가 보인다". C의 타입·포인터가 이 기계상을 반영 (27장의 씨앗).

**4장. 주소의 특수 지식 — 0번지, 정렬, 하위 비트**
0번 주소의 플랫폼별 특별함(보호 모드=접근 금지 페이지, 임베디드=벡터
테이블 등 유효 메모리), 정렬 제한(위반 시 플랫폼별 결과), 하위 주소
비트의 활용(태그 포인터 — 실제 런타임·GC 사례) (28·29장의 씨앗).

**5장. 속도의 기계장치 ↔ 표준의 탄생(C89)**
다층 캐시·파이프라인·분기 예측 — 단순한 모델이 무너지는 곳. 방언 난립과
계약으로서의 ANSI C. 실제 사례: 캐시 친화/비친화 실측, 분기 예측 실패 비용.

**6장. 컴파일러 최적화 ↔ 추상 기계(C99·C11)**
컴파일러는 그대로 번역하지 않는다 — "관찰 가능한 결과가 같다면" 자유.
그 근거인 추상 기계와 표준의 정밀화(엄격한 앨리어싱, 메모리 모델)
(39장 UB의 씨앗).

**7장. 그래서 C는 추상적인 언어다 ↔ 현재(C17·C23)**
기계어의 별명이 아니라 추상 기계의 언어 — 추상적으로 접근해야 하는 이유.
오개념: "C는 하드웨어 직접 조작 언어다". 최신 흐름: 포인터
프로버넌스 등 엄격해지는 포인터 제한 (29·39장의 씨앗).

**8장. 문자와 텍스트 ↔ 표준 속의 흉터**
EBCDIC, ASCII, ISO 646 국가 변형(`{ } [ \` 자리가 다른 글자) → 삼중자·
이중자의 존재 이유와 C23의 삼중자 제거. ISO 8859 Latin 계열, 멀티바이트의
혼란, 유니코드, 가변 길이 인코딩과 UTF-8. 수학 박스: 코드 포인트 공간,
UTF-8 바이트 구조 (31장의 씨앗).

**9장. 수의 표현 ↔ IEEE 754라는 계약**
고정소수점(위치=약속; 임베디드·금액)과 부동소수점(과학적 표기법의 기계판),
벤더 난립을 통일한 IEEE 754(1985) — C89와 같은 시대·같은 이유의 계약.
부호·지수·가수, 유한하고 근사하는 수의 세계. 오개념: "컴퓨터는 수학을
잘한다" (37장의 씨앗).

**10장. CPU와 GPU, 그리고 스트림의 기원**
CPU=지연시간의 기계(5장 장치들의 회수) vs GPU=처리량의 기계, CUDA·OpenCL이
C 방언인 이유, C의 추상 기계는 CPU상(像). 이어서 입출력이 "문자가 한 줄씩
흐르는 것"인 이유 — 펀치카드(80컬럼), 라인프린터, 프린터 터미널(`tty`,
`\n`, 행 버퍼링), 화면 터미널은 그 흉내 → C 스트림 모델의 계보
(11·17장의 씨앗). 집필 중 비대해지면 CPU/GPU와 스트림을 분리한다.

### 제3부 — 첫 프로그램 [사용자 확정: 헬로 월드와 개발환경]

**11장. 헬로 월드**
첫 프로그램을 지면에서 시연하고 한 줄씩 읽는다. `printf`는 아직 "주문" —
14~17장이 해부한다(의도된 선행 노출). 심화 문답: 10장 스트림 회수 —
"`printf`가 찍는 곳은 왜 '화면'이 아니라 '표준 출력 스트림'인가".

**12장. 일반적인 컴파일 과정**
전처리→컴파일→어셈블→링크를 gcc·clang 기반으로. 심화 문답: 2장 추상화
계층 회수 — "컴파일러는 몇 층에서 몇 층으로 내려가는 번역인가"
(19·40장의 씨앗).

**13장. 개발환경 구축**
특정 플랫폼 하나를 예시로 제시하되 일반론 위주(플랫폼 선정은 §4 미결).
gcc/clang 설치와 첫 빌드 확인 — 단, 시연으로 보여 줄 뿐 따라 하기를
요구하지 않는다(R16).

### 제4부 — 최소한의 도구 상자 [사용자 확정: 사용법 먼저]

관통 서사: "11장 헬로 월드 한 편을 완전히 읽어 낸다".

**14장. 프로그램의 구조**
`#include`라는 준비, `main`이라는 약속된 출발점, 문장과 블록, 세미콜론,
주석. "위에서 아래로 한 문장씩" 실행 모델(2장 계산 모델의 회수).

**15장. 수식 — 값이 되는 것**
값, 리터럴, 연산자, 평가. **기본 산술 최소 집합만**: `+ - *` 와 괄호.
나눗셈은 정수의 진실이 필요하므로 22장으로 예고만. 우선순위는 외우게
하지 않는다 — 괄호 관행.

**16장. 함수 사용 — 부르는 법**
만드는 법이 아니라 부르는 법: 호출, 인자, 반환값. `printf`도 함수
호출이었다는 것.

**17장. 출력**
`printf` 서식의 최소(`%d`, `%s`, `\n`). 입력은 저장할 곳(변수)이 필요해
아직 못 한다는 예고 — 제5부의 동기. 심화 문답: 10장 스트림 회수.

### 제5부 — 선언: 이름을 만드는 법 [사용자 확정]

**18장. 변수 선언**
선언 = 이름과 타입의 약속. 변수 = 이름 붙은 기억 장소(3장 주소의 회수 —
이름은 주소의 사람용 별명). 타입 = 값의 집합 + 연산의 약속. 초기화 우선,
`const`. 대입 `=` = 상태 변화. 오개념: `x = x + 1` 은 방정식이 아니다.

**19장. 함수 선언과 정의**
원형 = 함수의 계약 서명, 정의 = 몸통. 매개변수와 반환. 선언/정의 구별이
필요한 이유(컴파일러는 위에서 아래로 — 12장 회수, 40장의 씨앗).
스코프 첫걸음(블록 안의 이름은 밖에서 안 보인다).

**20장. 입력**
저장할 곳이 생겼으니 이제 입력을 받는다(17장 예고의 완결). 입력의 기초
한 가지와 "안전한 입력은 왜 어려운가" 예고(32장 proven의 씨앗).

구조체·공용체 같은 **타입을 만드는 선언은 여기서 다루지 않는다** —
메모리 모델 이후(제8부) [사용자 확정].

### 제6부 — 값과 흐름

**21장. 정수 — 유한한 수의 세계**
비트 폭, 부호 없는 정수 = 모듈러 산술(수학 박스: mod 2^n 합동), 부호 있는
정수 = 2의 보수, 오버플로. 실제 사례: 오버플로 사고. C23 `_BitInt`·
`<stdint.h>` 우선 관행. 심화 문답: 3장 워드 회수.

**22장. 정수의 연산 — 나눗셈, 비트**
15장에서 미룬 `/ %` — 버림과 나머지의 수학(수학 박스: 몫·나머지 정리),
비트 연산, 형변환의 첫걸음.

**23장. 불리언과 비교**
C23 `bool`, 비교 연산자, 논리 연산자와 단락 평가.

**24장. 결정 — if와 switch**
분기. 심화 문답: 5장 분기 예측 회수 — "if 는 공짜가 아니다".

**25장. 반복 — 루프와 불변식**
루프 3형제, 증감·복합 대입, 루프 불변식의 착상(수학 박스). 2장 계산
모델("단순한 단계의 반복")의 회수.

**26장. 함수의 의미 — 값 복사와 부수효과**
함수 = 수학적 함수와 절차의 사이. 인자 전달 = 값 복사(오개념: "변수를
넘긴다"), 스코프와 수명의 정식 취급, 재귀의 첫 만남, `?:`. 계약의 착상:
전제조건·후조건(38장의 씨앗).

### 제7부 — 기억

**27장. 객체, 주소, 포인터**
3장 워드·주소를 C 객체 모델로 정식화. 포인터 = 주소를 값으로. `& *`,
`sizeof`. 오개념: 포인터=정수, 미초기화. 그림(이중 부호화) 집중.

**28장. 널 — 삼형제의 구별**
널 문자 `'\0'` · 널 포인터 · `NULL`/C23 `nullptr` (닮은 이름 오개념).
소스의 0 = 널 포인터 상수라는 계약 vs 내부 표현은 0이 아닐 수 있다는
현실 — 4장 "0번지의 특별함" 회수(임베디드 0번지 유효 메모리와 널 검사).

**29장. 포인터의 규칙 — 정렬과 프로버넌스**
정렬과 포인터(4장 회수: 왜 `char*`는 아무 데나 가리켜도 되는가),
프로버넌스의 실무 감각(7장 회수), 포인터≠배열 예고.

**30장. 배열**
연속된 기억, 경계, 버퍼 오버런(실제 사례: 역사적 보안 사고), 배열과
포인터의 관계(오개념 정면 대응).

**31장. 문자열**
문자열 = 바이트 열 + NUL 종단 약속. 8장 인코딩 회수: char=바이트, UTF-8
리터럴, `u8""`.

**32장. 안전한 입력과 proven의 등장**
20장 예고의 실체: 왜 입력이 위험한가(오버런). **proven 첫 등장** — 경계
검사되는 문자열/입력 처리가 왜 필요한가.

**33장. 수명과 저장 기간**
자동/정적 저장 기간, 스코프와 수명의 구별(26장 회수), 댕글링의 첫 경고.

**34장. 동적 메모리**
`malloc`/`free`, 소유라는 개념, 댕글링·이중 해제(실제 사례), proven의
안전한 할당 관행.

### 제8부 — 자료의 모양 [사용자 확정: 후행 배치]

**35장. 구조체**
타입을 만드는 선언(제5부에서 미룬 것). `. ->`, 복합 리터럴, 자료구조의
첫걸음.

**36장. 공용체와 표현**
같은 기억을 다른 눈으로 읽기 — 엔디안 관찰 시연(3장 회수), 타입 퍼닝의
주의, 패딩과 정렬(4장 회수), 표현과 추상의 분리.

### 제9부 — 정밀

**37장. 실수 — 근사의 수학**
9장 IEEE 754 회수 → C float/double 실무: 유한 이진 유리수 부분집합, 반올림,
누적 오차(실제 사례), 비교의 함정(오개념: `0.1 + 0.2`). proven의 정확한
float 파싱·포매팅이 어려운 문제임을 사례로.

**38장. 오류와 계약**
오류는 예외가 아니라 값이다, 반환값 검사, proven식 계약(입력 검증·불변식·
명시적 전파). 심화 문답: 26장 전제조건 회수.

**39장. 정의되지 않은 동작**
UB(수학 박스: 부분 함수), 왜 존재하는가 — 6·7장 회수로 절반은 이미 답.
엄격한 앨리어싱·프로버넌스 정식 취급, 대표 UB와 회피, 새니타이저 시연.
실제 사례: UB 결함.

### 제10부 — 구성

**40장. 여러 파일 — 분할과 링크**
12장 컴파일 과정의 다중 파일 확장. 헤더=선언의 묶음(19장 회수), 번역
단위, 내부/외부 연결, 링크 오류 읽는 법.

**41장. 표준 라이브러리의 지형**
표준 라이브러리 훑기, 왜 보강이 필요한가.

**42장. proven 전면**
proven 설계 철학(검증된 기본기)과 실제 사용, 지금까지의 예제 재구성.

**43장. 모던 C 총정리**
C23 회고(이미 자연스럽게 써 온 것들), 현대적 스타일, 더 나아갈 길.
전권 회고 심화 문답으로 마무리.

## 3. RFC-0001 매핑 요약

- 소형 장 경량 템플릿(§1): 선행조직자 1~2문장 + 심화 문답 1~3개 + 오개념·실제 사례는 부 안에서 고르게.
- 씨앗-회수 다리(주요): 3장 워드·주소·엔디안→27·36장, 4장 0번지·정렬·태그→28·29·36장, 6·7장 최적화·추상 기계·프로버넌스→29·39장, 8장 인코딩→31장, 9장 IEEE 754→37장, 10장 스트림→11·17장, 12장 컴파일 과정→19·40장, 17·20장 입력 예고→32장, 26장 계약→38장. 제2부가 저수지이므로 다리의 절반 이상이 제2부에서 나온다.
- proven은 32장 첫 등장 → 42장 전면화. 그 전은 표준 C만.

## 4. 미결

- 13장 예시 플랫폼: (a) Windows+WSL/MSYS2 (b) Linux 데스크톱 (c) 둘 다 짧게.
- 20장 입력의 구체 선택: `scanf` 최소 vs 줄 읽기 우선 — 32장 안전성 서사와의 접속 기준으로 표본 집필에서 결정.
- 장 분할·병합 미세 조정: 집필하며 6~12쪽 목표를 넘거나 못 미치면 조정(예: 10장 CPU/GPU·스트림 분리).
- 부록 구성(설치 상세, ASCII/UTF-8 표, 연산자 전체 표 등).

## 5. 대안 검토

- **문법 항목 순서**: R05로 배제.
- **프로젝트 관통형**: 실습 없는 책과 충돌, "직전 예제의 변형"으로 연속성만 취함.
- **proven 처음부터**: "C를 배우는가 라이브러리를 배우는가"가 흐려져 배제. 필요가 증명된 시점(32장) 도입.
- **선언 먼저 사용 나중**(전통): 동기가 서지 않아 배제 (rev.b).
- **대형 장 유지**(rev.b): 한 장의 완주 부담이 크고 전환이 느려 배제 (rev.c, 사용자 확정). 내용은 전부 보존하고 단위만 쪼갬.

## 6. 자연스러움 검토 (rev.c 갱신)

- 11장 헬로 월드가 `printf`를 설명 없이 쓴다 → 의도된 선행 노출. 제4부가 해부한다(14장 선행조직자에 명시).
- 15장 수식이 변수 없이 성립하는가 → 성립(리터럴+호출). 변수는 18장에서 "수식에 넣을 수 있는 이름"으로 합류.
- 출력(17)은 변수 없이 성립, **입력(20)은 변수 필요 → 제5부 끝으로 배치**. 17장의 예고가 제5부의 동기를 만든다.
- 21·22장(정수)이 23~25장(비교·분기·루프)보다 앞 → 루프 카운터·비교가 정수 의미론을 전제. 정당.
- 26장(함수 의미론)이 25장 뒤 → 함수 몸통 예제에 조건·반복 필요. "사용(16)→선언(19)→의미(26)" 3단 나선. 정당.
- 제7부 순서(포인터→널→규칙→배열→문자열→안전 입력→수명→동적) → 각 장이 직전 장을 요구. 32장 proven 등장은 31장 문자열의 위험이 실체를 드러낸 직후 — 필요가 증명된 시점. 정당.
- 제8부(구조체·공용체)가 제7부 뒤 → 구조체 포인터·동적 자료구조로 바로 이어짐. 공용체 엔디안 시연은 3장 회수. [사용자 확정: 후행]
- 제9부(실수→오류→UB) → 실수 비교 함정이 오류 서사의 도입 사례, 계약(38)과 어두운 계약(39)의 대구. 정당.
- 소형 장 위험 — 파편화(장마다 맥락 재설정 비용): 부 서두에 부 전체 선행조직자를 두고, 장 사이 다리 문단을 의무화해 완화. 표본 집필(제2부)에서 검증.
