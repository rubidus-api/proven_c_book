- Status: Accepted

- Scope: 부(Part)와 장(Chapter)의 체계, 각 장의 역할과 RFC-0001 장치 매핑.
- 전제: RFC-0001 교수 설계 (읽기 전용 문답형). 기존 C 입문서 목차 답습 금지 (R05).

## 1. 구성 원리

**개념의 의존 순서**: 각 장은 앞 장까지의 개념만으로 완전히 설명 가능해야
하고, 다음 장의 심화 문답이 소환할 거리를 남겨야 한다. 문법은 개념이
필요로 하는 시점에 그 개념의 표기법으로 등장한다.

**사용이 정의보다 먼저다**: 먼저 남이 만든 것을 읽고 쓰는 법(제4부),
그다음 스스로 이름을 만드는 법(제5부).

**나선형 최소 집합** [사용자 확정]: 한 장에 한 주제를 다 넣지 않는다.
최소 집합부터 시작해 뒤 장들이 필요해지는 시점마다 덧붙여 규모를 불린다.
연산자 배분표:

| 시점 | 덧붙는 연산자/수식 요소 |
|---|---|
| 17장 | 기본 산술 최소 집합: `+ - *`, 괄호, 리터럴, 호출 |
| 20장 | 대입 `=` |
| 23·24장 | `/ %`, 비트 연산, 형변환 첫걸음 |
| 25~27장 | 비교, 논리 `&& \|\| !`, 증감 `++ --`, 복합 대입 |
| 28장 | 조건 연산자 `?:`, 쉼표의 함정 |
| 29장 | `& *`(주소·역참조), `sizeof` |
| 37장 | `. ->`, 복합 리터럴 |

연산자 전체 표는 부록 참조 자료.

**소형 장, 빠른 전환** [사용자 확정, rev.c]: 한 장 = 하나의 착상, 대략
6~12쪽. 큰 주제는 부(部)가 담고, 부 안에서 소형 장들이 이어달린다.
RFC-0001 §5 장 템플릿은 경량 적용: 선행조직자 1~2문장, 심화 문답 1~3개,
오개념·실제 사례는 부 안에서 고르게. 파편화 방지: 부 서두 선행조직자 +
장 간 다리 문단 의무.

축 세 가지(유지): **수학적 기반**(R07) · **기계 현실** · **안전 우선**.

## 2. 부·장 체계 (10부 45장)

### 제1부 — 바탕

**1장. 배경설명** [사용자 확정, 집필 완료]
프로그래밍이란 무엇인가, C는 어디에 있는가, 지금 C 세계의 요동(표준 병립·
C++/Rust/Zig·C의 변화 조짐), 왜 이 책인가 + proven 정직 공개, 읽는 법
4원칙. 심화 문답 없음(첫 장).

### 제2부 — 전산의 기본과 배경지식 [사용자 확정: 상당한 분량 = 이 부 전체]

이후 모든 부가 심화 문답으로 소환할 배경지식의 저수지. **이중 트랙
서사**: 각 장이 [기계 이야기 ↔ 그 시점의 C 역사] 쌍. 관통 명제 — "C의
역사는, 기계가 복잡해질수록 언어가 기계의 별명에서 추상 기계의 계약으로
정밀해져 온 역사다". **기능적 역사 원칙**: 연대기·인물 나열은 빼고 지금의
C를 설명하는 역사만.

**초보자용 난이도 램프** — 세 묶음:

- **묶음 ① 기계와 기억 (2~4장)**: 손에 잡히는 이야기.
- **묶음 ② 표현의 사다리 (5~8장)**: 사물함에 정수→소수→글자→글자의 흐름을 담는 법.
- **묶음 ③ 속도와 추상 (9~12장)**: 개념적 등반 — 기억의 분화, 속도의
  기계장치, 컴파일러 최적화, 그리고 부의 논제 완성.

부 서두에 로드맵 선행조직자. 각 장은 비유 앵커 하나 + 앞 장 회수 사슬.

**2장. 단순한 기계 모델 ↔ C의 탄생** [집필 완료]
CPU·메모리·클록, 계산 모델, 비트와 이진법(+바이트 크기 비고정·C23 바이트
정의·CHAR_BIT≥8·옥텟), C의 탄생 + **pre-K&R 족보**[사용자 지시]:
CPL→BCPL(단일 타입)→B(PDP-7, `++`)→PDP-11 바이트 주소화가 타입을
강제→C(리치, 1971~73) — C의 바이트 지향·포인터 중심·헐거운 타입의
기원을 기능적 역사로 설명, `=+`→`+=` 일화, "표준 없던 시절"→10장 다리.
Unix 이식성 혁명. 수학 박스: 위치 기수법.

**3장. 워드와 주소 ↔ C의 원형** [집필 완료]
사물함 복도(주소), 주소도 수다(29장 포인터의 씨앗), 워드(32/64비트의
의미), 리틀/빅 엔디안 대조 도해 + 리틀 엔디안의 장점(시작 주소 불변·
자리올림 방향 일치), NUXI 사례, 네트워크 바이트 순서 (38장 공용체 시연
예고).

**4장. 주소의 특수 지식 — 0번지, 정렬, 하위 비트** [집필 완료]
0번지의 플랫폼별 특별함(보호 모드=금지 구역, 임베디드=벡터 테이블),
널 포인터 도입 + 표현이 0이 아니었던 실제 기계들(Prime 50·CDC Cyber
180·Symbolics), 널 삼형제 얼굴 익히기(널 포인터/`NULL`·`nullptr`/NUL
문자 — 정식 취급은 30장), 정렬(격자 비유·이식성), 하위 비트 태그
포인터(런타임 사례, "0 아닌 없음"이 현역인 세계) (30·31·38장의 씨앗).

**5장. 정수의 표현 — 부호, 오버플로, 시프트** [사용자 지시로 신설, 집필 완료]
부호 없는 정수=모듈러 시계(수학 박스: mod 2^n, 팩맨 256판 킬 스크린
사례), 음수를 담는 세 가지 약속 — 부호-크기·1의 보수·2의 보수 — 의
경쟁(각각의 대가: 두 개의 0, 회로 복잡성)과 2의 보수의 우아함(수학
박스: 모듈러 재활용, -128 비대칭), C89~C17=세 표현 모두 허용→실기계는
2의 보수로 수렴→**C23이 2의 보수로 확정**(단 signed 오버플로는 여전히
UB — 표현과 의미의 구별을 명시). 오개념: "오버플로가 나면 알려 준다".
**시프트**: 왼쪽=0 채움(×2), 오른쪽=논리(0 채움)/산술(부호 채움) 두 벌,
폭 이상 시프트에서 CPU마다 다른 대응(x86=칸수 마스킹, 옛 ARM=0)→C의
UB — "기계들이 갈리는 곳은 계약 밖" 무늬의 첫 대면(41장의 씨앗).
C 정수 타입 실무는 23·24장이 이 배경 위에 선다.

**6장. 수의 표현 ↔ IEEE 754라는 계약** [비유: 부동소수점=과학적 표기법,
고정소수점=전부 "전" 단위로 적는 장부]
고정소수점과 부동소수점, 벤더 난립(IBM 헥스 플로트·VAX·Cray)을 통일한
IEEE 754(1985), 부호·지수·가수, 유한하고 근사하는 수. 오개념: "컴퓨터는
수학을 잘한다". 수학 박스: 형식 구조, 왜 0.1은 2진 유한소수가 아닌가
(39장의 씨앗).

**7장. 문자와 텍스트 ↔ 표준 속의 흉터** [비유: 문자 코드=우편 약어 협약]
문자=번호. EBCDIC, ASCII(0번=NUL — 4장 삼형제 회수), ISO 646 국가
변형(한국 독자용 실제 사례: 백슬래시 자리의 ₩), 삼중자·이중자와 C23의
삼중자 제거, ISO 8859, 멀티바이트 혼란(EUC-KR·문자 깨짐), 유니코드
코드 포인트, UTF-8 가변 길이 설계. 오개념: "한 글자=1바이트". 수학 박스:
코드 포인트 공간, UTF-8 바이트 구조 (33장의 씨앗).

**8장. 스트림의 기원 ↔ 펀치카드, 라인프린터, 프린터 터미널** [비유:
스트림=한 글자씩 흘러가는 띠]
펀치카드(80컬럼), 라인프린터, 텔레타이프(`tty`·`\r`/`\n`의 물리적 유래·
행 버퍼링), 화면 터미널=유리 텔레타이프, C 스트림 모델의 조상. 실제
사례: CRLF/LF 개행 혼란, 80컬럼의 잔재 (13·19장의 씨앗).

**9장. 기억의 분화 — 레지스터, 캐시, 다층의 사다리** [비유: 손안의
동전(레지스터), 책상 위의 책(캐시), 서가(메모리)]
서사 순서 확정 [사용자 지시]: ① 고백으로 연다 — 2장의 CPU·메모리·클록
모델이 얼마나 *과하게 간소화된* 그림이었는지부터 이야기한다(교수 장치로서
의 단순화였음을 정직하게 밝히고, 이제 그 그림을 수리해 간다는 선언).
② CPU 안에는 사실 **레지스터**가 있다 — 원래부터 있었고 매우 중요하다는
것을 강조한다: CPU는 메모리와 직접 계산하지 않는다, 모든 계산은 레지스터
위에서 일어난다(C의 `register` 키워드 흔적, 컴파일러가 변수를 레지스터에
올리는 일 — 11장 최적화의 씨앗). ③ 레지스터(수 개, 즉시)와 외부
메모리(수십억 칸, 느림)를 나란히 설명하고, 클록 상승과 함께 벌어진 둘
사이의 속도 격차의 역사. ④ 그 틈에 끼어든 **캐시** — 그리고 캐시의
분화(다층 L1/L2/L3 사다리). **캐시 라인**(캐시가 나르는 한 묶음 —
사물함 여러 칸을 상자째 나른다). 실제 사례: 2차원 배열 행/열 순회 실측
속도 차. 오개념: "메모리 접근은 어디나 같은 비용이다" (10장 false
sharing의 전제, 26장의 씨앗).

**10장. 속도의 기계장치 ↔ 표준의 탄생(C89)** [비유: 파이프라인=조립
라인, 분기 예측=단골 주문 미리 만들기]
파이프라인(한 박자에 여러 일 — 2장 GHz 문답의 회수), 분기 예측과 실패
비용(실제 사례: 정렬된 배열이 더 빠른 사건, 26장의 씨앗), 클록의 한계 →
**멀티코어**로의 방향 전환, 코어들이 캐시를 나눠 갖는 세계에서 생기는
**false sharing**(같은 캐시 라인을 두 코어가 다투는 사고 — 9장 캐시
라인의 회수). 역사 트랙 [사용자 지시: ANSI 이전사 포함]: 표준 이전의
C — 1978년 K&R 책("The C Programming Language")이 *사실상의 표준*이던
시절, Unix와 함께 대학·업계로 퍼지며 컴파일러마다 방언이 갈라진 과정
(원형 없는 함수 선언, 암묵 int 등 그 시절 어법), 이식 현장의 혼란 →
1983년 ANSI 위원회(X3J11) 결성 → 1989년 C89: 함수 원형 도입 등 언어
정비와 함께 프로그래머-구현 간 계약이 처음 명문화됨. 파이프라인 절에서
루프 언롤링을 소개하며 **Duff's device**(1983)를 이름·사연만 예고한다
(코드는 의존 순서상 불가 — 27장에서 정식 시연) [사용자 제안, 나선 배치].

**11장. 컴파일러 최적화 ↔ 추상 기계(C99·C11)** [비유: 컴파일러=직역가가
아니라 뜻만 지키는 편집자]
컴파일러는 그대로 번역하지 않는다 — "관찰 가능한 결과가 같다면" 재배열·
제거·변형의 자유. 그 근거인 표준의 추상 기계와 정밀화(엄격한 앨리어싱,
메모리 모델). 실제 사례: 비밀번호 지우는 memset이 최적화로 사라진 보안
사고 (41장 UB의 씨앗).

**12장. 그래서 C는 추상적인 언어다 — 그리고 어느 기계의 언어인가**
[비유: 표준=계약서, 추상 기계=계약서 속의 가상 기계]
부의 논제 완성. C는 추상 기계의 언어(9~11장의 필연적 결론). 오개념:
"C는 하드웨어 직접 조작 언어다". 최신 흐름: 포인터 프로버넌스 (31·41장의
씨앗). 마무리 파노라마 — CPU(지연시간) vs GPU(처리량), CUDA·OpenCL이 C
방언인 이유, C의 추상 기계는 CPU상(像).

### 제3부 — 첫 프로그램 [사용자 확정]

**13장. 헬로 월드**
첫 프로그램 지면 시연·한 줄씩 읽기. `printf`는 아직 "주문"(제4부가 해부,
의도된 선행 노출). 심화 문답: 8장 스트림 회수.

**14장. 일반적인 컴파일 과정**
전처리→컴파일→어셈블→링크, gcc·clang 기반. 심화 문답: 2장 추상화 계층
회수 (20·42장의 씨앗).

**15장. 개발환경 구축**
예시 플랫폼 하나 + 일반론 위주(§4 미결). 시연만, 따라 하기 요구 없음(R16).

### 제4부 — 최소한의 도구 상자 [사용자 확정: 사용법 먼저]

관통 서사: "13장 헬로 월드 한 편을 완전히 읽어 낸다".

**16장. 프로그램의 구조**
`#include`, `main`, 문장과 블록, 세미콜론, 주석. "위에서 아래로 한
문장씩"(2장 회수).

**17장. 수식 — 값이 되는 것**
값·리터럴·연산자·평가. 기본 산술 최소 집합만: `+ - *` 와 괄호. 나눗셈은
24장으로 예고만. 괄호 관행.

**18장. 함수 사용 — 부르는 법**
호출, 인자, 반환값. `printf`도 함수 호출.

**19장. 출력**
`printf` 서식 최소(`%d` `%s` `\n`). 입력은 변수가 필요해 예고만(제5부
동기). 심화 문답: 8장 스트림 회수.

### 제5부 — 선언: 이름을 만드는 법 [사용자 확정]

**20장. 변수 선언**
선언=이름과 타입의 약속, 변수=이름 붙은 기억 장소(3장 회수), 타입=값의
집합+연산의 약속, 초기화 우선, `const`, 대입 `=`. 오개념: `x = x + 1`.

**21장. 함수 선언과 정의**
원형=계약 서명, 정의=몸통, 선언/정의 구별의 이유(14장 회수, 42장 씨앗),
스코프 첫걸음.

**22장. 입력**
19장 예고의 완결. 입력의 기초 한 가지 + "안전한 입력은 왜 어려운가"
예고(34장 proven의 씨앗).

구조체·공용체 같은 타입 만드는 선언은 제8부로 미룬다 [사용자 확정].

### 제6부 — 값과 흐름

**23장. 정수 — 유한한 수의 세계**
비트 폭, unsigned=모듈러 산술(수학 박스: mod 2^n), signed=2의 보수,
오버플로(실제 사례), C23 `_BitInt`·`<stdint.h>`. 심화 문답: 3장 워드·5장 표현(2의 보수·오버플로) 회수.

**24장. 정수의 연산 — 나눗셈, 비트**
17장에서 미룬 `/ %`(수학 박스: 몫·나머지 정리), 비트 연산, 형변환 첫걸음.

**25장. 불리언과 비교**
C23 `bool`, 비교, 논리 연산자와 단락 평가.

**26장. 결정 — if와 switch**
분기. 심화 문답: 10장 분기 예측 회수 — "if 는 공짜가 아니다".

**27장. 반복 — 루프와 불변식**
루프 3형제, 증감·복합 대입, 루프 불변식(수학 박스), 2장 계산 모델 회수.
실제 사례: 루프 언롤링과 **Duff's device** 정식 시연(10장 예고의 회수 —
switch 폴스루(26장)와 루프의 기묘한 결합, 그 시절 왜 통했고 오늘날 왜
컴파일러에게 맡기는가).

**28장. 함수의 의미 — 값 복사와 부수효과**
수학적 함수와 절차의 사이, 값 복사(오개념: "변수를 넘긴다"), 스코프와
수명, 재귀, `?:`. 계약의 착상(40장의 씨앗).

### 제7부 — 기억

**29장. 객체, 주소, 포인터**
3장을 C 객체 모델로 정식화. `& *`, `sizeof`. 오개념: 포인터=정수,
미초기화. 그림 집중.

**30장. 널 — 삼형제의 정식 취급**
4장 얼굴 익히기의 심화: `'\0'`/널 포인터/`NULL`·`nullptr` 구별, 소스의
0=널 포인터 상수라는 계약 vs 내부 표현은 0이 아닐 수 있다는 현실(4장
사례 회수 + memset으로 포인터를 0 채우는 함정), 임베디드 0번지와 널 검사.

**31장. 포인터의 규칙 — 정렬과 프로버넌스**
정렬과 포인터(4장 회수), 프로버넌스 실무 감각(12장 회수), 포인터≠배열
예고.

**32장. 배열**
연속된 기억, 경계, 버퍼 오버런(실제 사례), 배열과 포인터의 관계.

**33장. 문자열**
바이트 열+NUL 종단 약속. 7장 인코딩 회수: char=바이트, UTF-8 리터럴,
`u8""`.

**34장. 안전한 입력과 proven의 등장**
22장 예고의 실체(오버런). proven 첫 등장 — 경계 검사되는 처리의 필요.

**35장. 수명과 저장 기간**
자동/정적, 스코프와 수명 구별(28장 회수), 댕글링 첫 경고.

**36장. 동적 메모리**
`malloc`/`free`, 소유, 댕글링·이중 해제(실제 사례), proven의 안전한 할당.

### 제8부 — 자료의 모양 [사용자 확정: 후행 배치]

**37장. 구조체**
타입을 만드는 선언(제5부에서 미룬 것). `. ->`, 복합 리터럴, 자료구조
첫걸음.

**38장. 공용체와 표현**
같은 기억을 다른 눈으로 — 엔디안 관찰 시연(3장 회수), 타입 퍼닝 주의,
패딩과 정렬(4장 회수), 표현과 추상의 분리.

### 제9부 — 정밀

**39장. 실수 — 근사의 수학**
6장 IEEE 754 회수 → C float/double 실무: 반올림, 누적 오차(실제 사례),
비교의 함정(오개념: `0.1 + 0.2`), proven의 정확한 float 처리 사례.

**40장. 오류와 계약**
오류는 값이다, 반환값 검사, proven식 계약. 심화 문답: 28장 회수.

**41장. 정의되지 않은 동작**
UB(수학 박스: 부분 함수), 왜 존재하는가(10·12장 회수), 엄격한 앨리어싱·
프로버넌스 정식 취급, 대표 UB·회피, 새니타이저 시연, 실제 사례.

### 제10부 — 구성

**42장. 여러 파일 — 분할과 링크**
14장의 다중 파일 확장. 헤더=선언의 묶음(21장 회수), 번역 단위, 연결,
링크 오류 읽기.

**43장. 표준 라이브러리의 지형**
표준 라이브러리 훑기, 왜 보강이 필요한가.

**44장. proven 전면**
proven 철학과 실제 사용, 예제 재구성.

**45장. 모던 C 총정리**
C23 회고, 현대적 스타일, 더 나아갈 길. 전권 회고 심화 문답.

## 3. RFC-0001 매핑 요약

- 소형 장 경량 템플릿(§1).
- 씨앗-회수 다리(주요): 3장 워드·주소·엔디안→29·38장, 4장 0번지·정렬·태그·널→30·31·38장, 5장 정수 표현·시프트→23·24·41장, 6장 IEEE 754→39장, 7장 인코딩→33장, 8장 스트림→13·19장, 9장 캐시 라인→10장(false sharing)·27장, 10장 분기 예측→26장, 11·12장 최적화·추상 기계·프로버넌스→31·41장, 14장 컴파일 과정→21·42장, 19·22장 입력 예고→34장, 28장 계약→40장. 제2부가 저수지 — 다리의 절반 이상이 제2부에서 나온다.
- proven은 34장 첫 등장 → 44장 전면화. 그 전은 표준 C만.

## 4. 미결

- 15장 예시 플랫폼: (a) Windows+WSL/MSYS2 (b) Linux 데스크톱 (c) 둘 다 짧게.
- 22장 입력의 구체 선택: `scanf` 최소 vs 줄 읽기 — 34장 안전성 서사 기준, 표본 집필에서 결정.
- 장 분할·병합 미세 조정(6~12쪽 기준; 예: 12장이 크면 CPU/GPU 분리).
- 부록 구성(설치 상세, ASCII/UTF-8 표, 연산자 전체 표 등).

## 5. 대안 검토

- 문법 항목 순서: R05로 배제.
- 프로젝트 관통형: 실습 없는 책과 충돌 — "직전 예제의 변형"으로 연속성만.
- proven 처음부터: 배제, 필요 증명 시점(34장) 도입.
- 선언 먼저 사용 나중(전통): 동기 부재로 배제(rev.b).
- 대형 장 유지: 배제(rev.c).
- 속도 단일 장(rev.d까지): 기억의 분화(계층·캐시 라인)와 실행의 기계장치(파이프라인·분기·멀티코어)는 서로 다른 착상이라 rev.e에서 분할. false sharing은 두 장의 개념(캐시 라인 × 멀티코어)이 만나는 지점이라 10장 말미가 자연 위치.

## 6. 자연스러움 검토

- 13장 헬로 월드의 `printf`=의도된 선행 노출(제4부 해부).
- 17장 수식은 변수 없이 성립. 출력(19)은 변수 없이, 입력(22)은 변수 뒤 — 제5부 동기.
- 23·24(정수)→25~27(비교·분기·루프)→28(함수 의미): 의존 정당. "사용(18)→선언(21)→의미(28)" 3단 나선.
- 제7부: 각 장이 직전 장을 요구. proven(34)은 문자열 위험(33) 직후=필요 증명 시점.
- 제8부 후행: 구조체 포인터·동적 자료구조 즉시 가능. 공용체 엔디안 시연=3장 회수.
- 제9부: 실수 비교 함정→오류 서사 도입, 계약(39)↔어두운 계약(40) 대구.
- (rev.d) 제2부 램프: 만질 수 있는 것(2~8)이 앞, 눈에 안 보이는 것(9~12)이 뒤. 9~12장은 C 역사 시간순(C89→C99/C11→C17/C23)과 일치. 6·7장의 역사 훅이 10장 C89보다 먼저 나오는 시대 역전은 기능적 역사 원칙상 허용.
- (rev.e) 9장(기억의 분화)→10장(기계장치) 순서: 캐시 라인 개념이 false sharing의 전제이므로 8이 9보다 앞이어야 한다. 멀티코어는 "클록 한계"에서 자연 도입되어 파이프라인·분기 예측과 같은 장에 있는 것이 서사상 맞다. 레지스터는 "원래부터 있던 것"으로 9장 서두에 배치해 2장(CPU 모델)과 잇는다.
- 소형 장 파편화 완화: 부 서두 선행조직자 + 장 간 다리 문단(유지).
