부록 B — printf·scanf 서식 완전 정리

19장에서 최소 집합(%d, %s, %%)을 익혔고, 48장에서 서식 문자열을 해부했다. 이 부록은 찾아보기 위한 자리다 — 필요한 줄만 짚어 읽으면 된다. 규칙 하나만 앞세운다: 서식과 인자의 타입이 어긋나면 계약 밖(정의되지 않은 동작)이다(42·48장).

서식 지정의 뼈대

출력과 입력의 문법은 닮았지만 뜻이 다르다. 먼저 두 뼈대를 나란히 둔다.

%.*s는 이 책에서 자주 쓴 형태다 — 길이를 따로 지니고 다니는 문자열(50·67장의 뷰)을 NUL 종단 없이 그대로 찍을 수 있기 때문이다.

길이 수식어 — 타입의 폭을 알려 주는 자리

가변 인자에는 타입 정보가 실려 가지 않으므로(46장), 이 글자가 곧 계약 이다. 틀리면 스택을 잘못 읽는다.

실수에는 특별한 주의가 필요하다. 출력에서 float은 기본 진급으로 double이 되므로 %f 하나면 되고 %lf도 같은 뜻이다. 입력에서는 진급이 없으므로 %f는 float *, %lf는 double *로 반드시 갈라야 한다(48장의 오개념 상자).

고정 폭 정수의 서식

int32_t 같은 타입은 플랫폼마다 실제 타입이 달라서, 서식을 손으로 적으면 어긋날 수 있다. 표준은 <inttypes.h>에 매크로를 두었다.

#include <inttypes.h>

uint64_t total = 1234567890123ULL;
printf("total = %" PRIu64 "\n", total);   /* 문자열 이어붙이기다 */

int32_t n = 0;
sscanf(line, "%" SCNd32, &n);

이름 규칙은 단순하다 — 출력은 PRI + 변환 + 폭(PRId32, PRIu64, PRIx16), 입력은 SCN + 변환 + 폭(SCNd32, SCNu64). 폭 자리에는 8·16·32·64 외에 MAX(PRIdMAX)와 PTR(PRIxPTR)도 온다.

%%% 글자—

억제 문자 *를 끼우면 읽되 저장하지 않는다 — sscanf(s, "%*d %d", &n)은 첫 수를 버리고 둘째 수만 받는다. 억제된 항목은 반환값에도 세지 않는다.

집합 지정자는 작은 도구 하나에 가깝다. %[abc]는 a·b·c만, %[^,\n]은 쉼표와 개행이 아닌 글자를 모은다. 범위 표기(%[a-z])는 널리 쓰이지만 표준이 보장하지는 않는다.

입력에서만 통하는 규칙들

  • 서식의 공백 한 칸은 “공백 몇 개든(없어도 좋다)”이다. 개행도 공백이다.
  • 서식의 보통 글자는 입력과 그대로 맞아야 한다. 어긋나면 매칭 실패로 그 자리에서 멈춘다.
  • 반환값은 성공적으로 채운 항목 수다. 입력이 이미 끝났으면 EOF(음수) 이고, 이는 “형식이 틀렸다”(0)와 다른 뜻이다.
  • 실패한 인자는 손대지 않는다. 확인 없이 쓰면 이전 값을 새 입력으로 착각한다(62장의 반례가 그것이다).
  • %c와 %[만 공백을 건너뛰지 않는다. 앞의 줄에서 남은 개행이 다음 %c로 들어가는 사고가 여기서 나온다 — " %c"처럼 앞에 빈칸을 넣으면 건너뛴다.
  • 오버플로를 알려 주지 않는다. %d에 99999999999를 주는 것은 계약 밖이다. 범위 검사가 필요하면 strtol 계열이나 68장의 스캐너를 쓴다.

snprintf의 반환값 규칙이 특히 중요하다 — 쓴 글자 수가 아니라 필요했던 글자 수이므로, 잘림 검사는 need >= (int)sizeof buf로 한다(62장).
