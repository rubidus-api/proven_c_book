부록 C — 암묵 변환 요약

28장의 규칙을 표로 압축한 것이다.

정수 승격

bool, char, signed char, unsigned char, short, unsigned
short, 비트 필드가 산술에 참여하면:

  • 값들이 전부 int에 담기면 → int
  • 아니면 → unsigned int

즉 산술은 int보다 좁은 타입 위에서 일어나지 않는다.

통상 산술 변환 (두 피연산자의 공통 타입)

  1. 한쪽이 long double → 둘 다 long double
  2. 아니고 한쪽이 double → 둘 다 double
  3. 아니고 한쪽이 float → 둘 다 float

  4. 둘 다 정수 → 각각 정수 승격 후:

    • 부호가 같으면 → 더 넓은 쪽
    • 부호 없는 쪽이 더 넓거나 같으면 → 부호 없는 쪽
    • 부호 있는 쪽이 더 넓고 상대 값을 다 담으면 → 부호 있는 쪽
    • 그 밖 → 부호 있는 쪽의 부호 없는 판

실무 요약: 섞이면 넓은 쪽으로, 폭이 같으면 부호 없는 쪽이 이긴다. 부호 섞인 비교는 피한다(경고를 켜 두면 컴파일러가 짚어 준다).

가변 인자의 기본 진급

원형에 타입이 없는 자리(...)로 넘어가는 인자:

  • float → double
  • bool·char·short 계열 → int(또는 unsigned int)

그래서 printf에 float 전용 서식이 없고, %f가 double을 받는다 (19·25·50장).

정수 변환 등급 (변환 규칙의 기준자)

통상 산술 변환이 “더 넓은 쪽”을 고를 때 쓰는 순서다. 위가 높다.

long long  >  long  >  int  >  short  >  char / bool

같은 폭이면 부호 없는 쪽과 부호 있는 쪽의 등급은 같고, 이때 부호 없는 쪽이 이긴다. 그래서 -1 < 1u가 거짓이 된다 — -1이 거대한 부호 없는 값으로 바뀌기 때문이다(28장).

어떤 변환이 어떤 위험을 부르는가

변환일어나는 일위험
부호 있는 → 부호 없는2의 보수 값이 그대로 재해석된다음수가 거대한 값이 된다
부호 없는 → 부호 있는담기면 그대로, 아니면 구현 정의경계에서 값이 바뀐다
넓은 정수 → 좁은 정수상위 비트를 버린다조용한 값 손실
정수 → 실수가까운 값으로 반올림큰 정수에서 정밀도 손실(8장)
실수 → 정수소수부를 버린다(0 방향)범위 밖이면 계약 밖
double → float정밀도를 줄인다반올림 오차
포인터 → void *무손실타입 정보만 잃는다
void * → 다른 포인터무손실정렬이 맞지 않으면 계약 밖(35장)
정수 → 포인터구현 정의출처(provenance)를 잃는다(14장)

조용한 변환이 일어나는 자리 목록

암묵 변환은 다음 자리에서 묻지 않고 일어난다.

  • 산술 연산의 두 피연산자 사이(통상 산술 변환)
  • 대입의 오른쪽 → 왼쪽 타입
  • 함수 인자 → 매개변수 타입(원형이 있을 때)
  • return의 값 → 반환 타입
  • 조건 자리(if, while, ?:의 조건) → bool 판정
  • ...로 넘어가는 인자(기본 진급)
  • 배열·함수 이름이 값으로 쓰일 때(포인터로 무너짐)

그 밖의 자주 만나는 변환

  • 축소(넓은 → 좁은 정수): 상위 비트가 잘린다(7장). 부호 있는 타입에서 값이 안 들어가면 구현 정의 동작이다.
  • 실수 → 정수: 소수부를 버린다(0을 향해). 범위를 벗어나면 계약 밖이다.
  • 배열 → 포인터: 대부분의 문맥에서 첫 원소 주소로 무너진다. 예외는 sizeof, alignof, &(36장).
  • 함수 → 포인터: 함수 이름은 함수 포인터로 무너진다.
